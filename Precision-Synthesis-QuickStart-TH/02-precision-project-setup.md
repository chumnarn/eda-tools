# บทที่ 2 — ตั้งค่าโปรเจกต์ Precision และสังเคราะห์

> **จุดยืนของบทนี้**: ครอบคลุมขั้นที่ 1 (Set-Up Precision: a–d) และขั้นที่ 2 (Run Synthesis: a–b)
> ของคู่มือ PS2018.1 อย่างละเอียดจนผู้เรียนทำตามได้ทีละขั้น

---

## 2.1 ขั้นที่ 1a — Create project

### 2.1.1 ทำใน GUI

```text
File > New Project...
  Project name : top_alu8
  Location     : <โฟลเดอร์งานของคุณ>/ps_lab
  [Create Project]
```

ตั้งชื่อโปรเจกต์ให้ตรงกับชื่อ top module เพราะ PS จะใช้ชื่อนี้เป็นชื่อเน็ตลิสต์
และเป็นชื่อ top ที่ Vivado จะใช้อ้างอิง

### 2.1.2 โครงสร้างโฟลเดอร์ที่แนะนำ

```text
ps_lab/
├── rtl/          ไฟล์ VHDL
├── sdc/          ไฟล์เงื่อนไขเวลา
├── ps/           โฟลเดอร์โปรเจกต์ Precision (สร้างอัตโนมัติ)
└── netlist/      เน็ตลิสต์ EDIF ที่ส่งต่อให้ Vivado
```

เตรียมโฟลเดอร์ `netlist/` ไว้ตั้งแต่ต้น เพราะผลลัพธ์ของ PS จะถูกส่งต่อไปที่นั่น

### 2.1.3 สิ่งที่ไม่ควรทำ

| อย่า | เพราะ |
|---|---|
| อย่าใส่ไฟล์ RTL ที่ยังไม่ผ่านการจำลอง | PS จะสังเคราะห์ผิดแล้วรายงานว่า "ผ่าน" ทำให้หลอกตัวเอง |
| อย่าเพิ่มไฟล์ Verilog และ VHDL ปนกันโดยไม่แก้ข้อกำหนดภาษา | PS จะเดาชนิดจากนามสกุลไฟล์ ซึ่งไม่เสมอไปตามความจริง |
| อย่าแก้ไฟล์ RTL ที่อยู่ในโฟลเดอร์ของ PS | PS จะจัดการไฟล์เหล่านั้นเอง ควรแก้ที่ต้นทางแล้วสังเคราะห์ใหม่ |

## 2.2 ขั้นที่ 1b — Add design source files

### 2.2.1 ชนิดไฟล์ที่ PS อ่านได้

ตามคู่มือ PS2018.1 Precision อ่านไฟล์ได้ 4 ชนิด

| ชนิด | หน้าที่ | ในแล็บนี้ใช้ไฟล์ใด |
|---|---|---|
| **VHDL** | โค้ดออกแบบ | `rtl/alu8.vhd`, `rtl/hex2seg.vhd`, `rtl/top_alu8.vhd` |
| **Verilog** | โค้ดออกแบบ (ทางเลือก) | ไม่ได้ใช้ในแล็บนี้ |
| **EDIF** | เน็ตลิสต์ที่สังเคราะห์มาแล้ว (เชื่อมต่อดีไซน์ใหญ่) | ไม่ได้ใช้ในแล็บนี้ |
| **SDC** | เงื่อนไขเวลา (ขั้นที่ 1d) | `sdc/top_alu8.sdc` |

> ในทางปฏิบัติโปรเจกต์ขนาดใหญ่จะมีทั้ง 4 ชนิดอยู่ด้วยกัน
> เช่น โมดูลหลักเป็น VHDL, IP core จากผู้ขายเป็น EDIF, และมี SDC รวม

### 2.2.2 เพิ่มไฟล์ใน GUI

```text
File > Add Files...
  [Add Files...] เลือกชนิดไฟล์ VHDL
  เลือก: alu8.vhd, hex2seg.vhd, top_alu8.vhd
  [OK]
```

**ลำดับการเพิ่มไฟล์สำคัญ**: PS ต้องเห็นโมดูลที่เป็น dependency ก่อน
จึงเพิ่ม `alu8.vhd` → `hex2seg.vhd` → `top_alu8.vhd` (leaf ก่อน top)

หลังเพิ่มแล้วให้ตรวจว่า PS รู้จัก hierarchy ถูกต้อง

```text
Design > Show Hierarchy
  ต้องเห็น:
    top_alu8
     ├── alu8
     └── hex2seg  (x2)
```

ถ้า hierarchy ไม่ถูกต้อง แสดงว่า:
- เพิ่มไฟล์มาผิดลำดับ → ลบแล้วเพิ่มใหม่
- ชื่อ entity ไม่ตรงกับชื่อที่ instantiate
- มีไฟล์ค้างอยู่ในโปรเจกต์ → ตรวจรายการไฟล์ทั้งหมด

### 2.2.3 ข้อควรระวังเรื่องไลบรารี

ถ้ามีโมดูลที่ต้อง "สังเคราะห์เป็นแบบตรง" (black box) ต้องระบุชัดเจน
มิฉะนั้น PS อาจสร้างเน็ตลิสต์ที่ไม่มีพินจริงและจะพังตอนวางวางใน Vivado

## 2.3 ขั้นที่ 1c — Select device

### 2.3.1 เลือกอุปกรณ์สำหรับ Nexys A7-100T

```text
Design > Environment Settings... > Setup Design
  Family        : Xilinx 7-Series (Artix-7)
  Device        : XC7A100T
  Package       : CSG324
  Speed Grade   : -1
  [OK]
```

หรือถ้ารุ่นที่ใช้แสดงเป็น "Part Number" ให้ใส่โดยตรง:

```text
  Part          : xc7a100tcsg324-1
```

### 2.3.2 ข้อมูลอุปกรณ์อ้างอิงสำหรับ Nexys A7-100T

| รายการ | ค่า |
|---|---|
| ผู้ผลิตชิป | Xilinx (AMD) |
| ตระกูล | Artix-7 (7-Series) |
| ชื่อ part | XC7A100T-1CSG324C |
| ใน Vivado | `xc7a100tcsg324-1` |
| Board part ใน Vivado | `digilentinc.com/nexys-a7-100T` |
| LUT | 63,400 |
| Flip-Flop | 126,800 |
| BRAM | 4,860 Kbit |
| DSP48E1 | 240 |
| Clock Management Tile | 6 |
| นาฬิกาหลักบนบอร์ด | 100 MHz ที่พิน E3 (MRCC, bank 35) |

> **ข้อควรรู้**: ความจุด้านบนคือของ XC7A100T ส่วนบอร์ด Nexys A7 มีให้เลือกสองรุ่น
> คือ A7-100T และ A7-50T ที่มี XC7A50T ตรวจสอบรุ่นของบอร์ดของตัวเองจากซีรีส์เลขท้องบนกล่อง
> หรือจาก Vivado Board Part

### 2.3.3 ทำไมการเลือก part จึงสำคัญมาก

เมื่อเลือก part แล้ว PS จะใช้ **ไลบรารีเซลล์จริง** ของอุปกรณ์ในการสังเคราะห์
ทำให้ได้ตัวเลขที่ใกล้เคียงความจริงมากขึ้น เช่น

- LUT ที่ต้องใช้จริง (ไม่ใช่จำนวน gate เชิงตรรกะ)
- ความหน่วงการเดินสายภายในเซลล์ (t_int, t_co)
- จำนวนรีจิสเตอร์ต่อเซลล์
- ข้อจำกัดของการใช้ DSP/BRAM

ถ้าไม่เลือก part รายงานเวลาจะเป็นค่าประมาณของตรรกะเชิงหลักการ
ซึ่งห่างจากความจริงมาก โดยเฉพาะกับ FPGA

### 2.3.4 ถ้ารุ่นที่ใช้ไม่มี Artix-7

PS2018.1 รองรับตระกูลอุปกรณ์ตามรุ่น จึงอาจมีกรณีที่รายการไม่มี Artix-7 ให้เลือก
มีทางออก 3 ทาง เรียงตามความเหมาะสม

1. **ใช้การสังเคราะห์แบบไม่ผูกกับอุปกรณ์ (generic)** — ได้ตัวเลขประมาณที่ใช้
   เปรียบเทียบสัดส่วนได้ แต่ใช้ตัดสินว่าผ่านบอร์ดจริงไม่ได้
2. **ส่งต่อเป็นเน็ตลิสต์ VHDL/Verilog แทน EDIF** แล้วให้ Vivado สังเคราะห์ต่อ
   (เสียข้อดีของการใช้ไลบรารีของอุปกรณ์ใน PS แต่ยังได้ผลลัพธ์บนฮาร์ดแวร์)
3. **อัปเกรดรุ่นของ PS** แล้วทำตามขั้นตอนเดิมทั้งหมด

## 2.4 ขั้นที่ 1d — Set Frequency

นี่คือขั้นตอนที่ถูกมองข้ามที่สุด และเป็นต้นเหตุของปัญหามากที่สุดในงานสังเคราะห์

### 2.4.1 สองวิธีที่ใช้ได้

**วิธีที่ 1 — ผ่าน GUI**

```text
Setup Timing > Add Clock...
  Clock name  : sys_clk
  Frequency  : 100 MHz
  [Add Clock]
```

ข้อดี: เร็วและตรงไปตรงมา
ข้อด้อย: ไม่บันทึกไว้ในไฟล์ ทำซ้ำไม่ได้ง่าย และตั้ง input/output delay ไม่ได้

**วิธีที่ 2 — ผ่านไฟล์ SDC (แนะนำ)**

```text
File > Add Files...  เลือกชนิด SDC  → เลือก sdc/top_alu8.sdc
```

เนื้อหาไฟล์ `sdc/top_alu8.sdc`

```tcl
create_clock -name sys_clk -period 10.000 -waveform {0.000 5.000} \
             [get_ports {CLK100MHZ}]

set_input_delay  -clock sys_clk -max 2.000 [get_ports {SW[*]}]
set_input_delay  -clock sys_clk -max 2.000 [get_ports {BTN[*]}]

set_output_delay -clock sys_clk -max 2.000 [get_ports {LED[*]}]
set_output_delay -clock sys_clk -max 2.000 [get_ports {AN[*]}]
set_output_delay -clock sys_clk -max 2.000 [get_ports {SEG[*]}]

set_false_path -from [get_ports {CPU_RESETN}]
```

### 2.4.2 อธิบายทีละบรรทัด

| คำสั่ง | ความหมาย | ถ้าไม่ใส่จะเกิดอะไร |
|---|---|---|
| `create_clock` | สร้างนาฬิกาหลัก 100 MHz (คาบเวลา 10 ns) | **ไม่มีเส้นทางไหนถูกจำกัดเวลาเลย** รายงานเวลาจะว่าง |
| `set_input_delay` | เวลาที่อินพุตจากภายนอกใช้ในการสร้าง | เส้นทางอินพุต → รีจิสเตอร์จะถูกมองว่า "ไม่จำกัด" |
| `set_output_delay` | เวลาที่ต้องใช้ในการขับเอาต์พุต | เส้นทางรีจิสเตอร์ → เอาต์พุตจะถูกมองว่า "ไม่จำกัด" |
| `set_false_path` | ตัดเส้นทางรีเซ็ตแบบ asynchronous | เส้นทางรีเซ็ตจะไปกวนการวิเคราะห์และอาจรายงานผิดพลาด |

### 2.4.3 ตรวจสอบว่าจำกัดครบแล้วหรือยัง

ก่อนสังเคราะห์ ให้รันการรายงานเส้นทางที่ไม่ถูกจำกัด

```text
Report > Timing > Unconstrained Paths
```

**เกณฑ์ผ่าน: ต้องไม่มีเส้นทางที่ไม่ถูกจำกัดเลย** (หรือถ้ามี ต้องอธิบายได้ว่าทำไมถึงยอมรับได้)

ถ้ายังไม่ได้สังเคราะห์ ให้รันหลังจาก Compile แล้ว
เพราะ PS ต้องรู้จัก hierarchy ก่อนจะตรวจเส้นทางได้

### 2.4.4 เทียบ SDC กับ XDC ใน Vivado

Vivado ใช้ XDC ซึ่งเป็นภาษา Tcl เหมือนกัน แต่มีข้อกำหนดของตัวเองเพิ่ม
(เช่น `set_property PACKAGE_PIN`) ในไฟล์ `labs/vivado/nexys_a7_100t.xdc` ของคู่มือนี้
ได้แยกส่วนที่เป็น "ข้อกำหนดการจัดวางพิน" ออกจาก "ข้อกำหนดเวลา" ให้เห็นชัด

| เรื่อง | SDC | XDC |
|---|---|---|
| รูปแบบ | Synopsys Design Constraints | Xilinx Design Constraints (ส่วนขยายของ SDC) |
| กำหนดเวลา | ได้ | ได้ |
| กำหนดพินชิป | ไม่ได้ | ได้ |
| ใช้กับ | Precision, Synopsys, Quartus | Vivado |

## 2.5 ขั้นที่ 2a — Compile

### 2.5.1 Compile ทำอะไร

ขั้นตอนนี้ PS จะ

1. อ่านไฟล์ RTL ทั้งหมดตามลำดับที่เพิ่มเข้ามา
2. ตรวจ syntax ของ VHDL
3. สร้าง hierarchy ของโมดูล
4. ระบุ top module และตรวจว่าพอร์ตของ top ตรงกับที่คาด
5. ตรวจว่ามี black box หรือโมดูลที่หาไม่พบ

### 2.5.2 วิธีรัน

```text
ปุ่ม Compile บนแถบเครื่องมือ
หรือ
Build > Compile
```

### 2.5.3 ข้อผิดพลาดที่พบบ่อย

| ข้อความ | สาเหตุ | วิธีแก้ |
|---|---|---|
| `Unable to find entity` | เพิ่มไฟล์มาผิดลำดับ | ลบแล้วเพิ่มใหม่ โดยเริ่มจาก leaf |
| `Top level module not specified` | ไม่ได้ตั้ง top | ตั้ง top module ใน Environment Settings |
| `Port width mismatch` | ชนิดข้อมูลของพอร์ตไม่ตรง (เช่น `std_logic` กับ `bit`) | แก้ให้ใช้ชนิดเดียวกันทั้งโมดูล |
| `No clocks found` | ยังไม่ได้ใส่ SDC หรือไม่ได้กำหนดความถี่ | ทำขั้น 1d |

## 2.6 ขั้นที่ 2b — Synthesize

### 2.6.1 สิ่งที่ PS ทำในขั้นนี้

```text
RTL
 │  การแปลงเป็นตรรกะเชิงบิต (bit-level logic synthesis)
 ▼
ตรรกะเชิงบิต
 │  การแมปเข้าเซลล์จริงของอุปกรณ์ (technology mapping)
 ▼
เน็ตลิสต์เซลล์
 │  การปรับปรุงเวลา (timing optimization)
 ▼
เน็ตลิสต์ที่ปรับปรุงแล้ว + รายงาน QoR
```

### 2.6.2 วิธีรัน

```text
ปุ่ม Synthesize บนแถบเครื่องมือ
หรือ
Build > Synthesize
```

ระหว่างรอ PS จะรายงานความคืบหน้าเป็นเฟส:
Logic Optimization → Technology Mapping → Timing Optimization

### 2.6.3 ตัวเลือกที่ควรรู้จัก

| ตัวเลือก | ผลต่อ QoR | ใช้เมื่อ |
|---|---|---|
| **Retiming** (เปิด/ปิด) | ย้ายรีจิสเตอร์ข้ามตรรกะ combinational เพื่อลดความหน่วงของเส้นทาง | ต้องการปรับปรุงเวลาแต่ไม่อยากเพิ่มจำนวนรีจิสเตอร์ |
| **Optimization effort** (ต่ำ/กลาง/สูง) | ยิ่งสูงยิ่งใช้เวลานานแต่ QoR ดีขึ้น | มีเวลาให้ลองหลายรอบเมื่อปิดเวลาไม่ผ่าน |
| **Resource sharing** | ลดจำนวนตัวคูณ/ตัวบวก | พื้นที่สำคัญกว่าเวลา |
| **Area optimization** | ลดพื้นที่ แลกกับเวลาที่ช้าลง | พื้นที่เป็นข้อจำกัดหลัก |

> **ข้อควรระวังเรื่อง Retiming**: การย้ายรีจิสเตอร์ข้ามขอบเขตโมดูลหรือข้ามพอร์ต I/O
> จะเปลี่ยนสมมติฐานของเส้นทาง I/O ทำให้เงื่อนไข SDC ที่เขียนไว้อาจไม่ตรงกับโครงสร้างใหม่
> ให้ตรวจรายงานเส้นทางหลังเปิด Retiming อีกครั้งเสมอ

## 2.7 การทำงานแบบสคริปต์ (Tcl)

### 2.7.1 เหตุผลที่ต้องทำแบบสคริปต์

- ทำซ้ำได้หลายรอบโดยไม่ต้องกดเมาส์ (จำเป็นสำหรับบทที่ 5 ที่ต้องรัน 2 รอบเปรียบเทียบ)
- เก็บไว้ในระบบควบคุมเวอร์ชัน
- ใช้เป็นเอกสารบอกขั้นตอนได้

### 2.7.2 วิธีที่ปลอดภัยที่สุด — ให้เครื่องมือสร้างสคริปต์ให้เรา

```text
ทำขั้นตอนทั้งหมดใน GUI ครั้งแรก
แล้ว
File > Save Command File...
บันทึกเป็น ps_build.tcl
```

สคริปต์ที่ได้จะเป็นคำสั่งที่ **คุณทำจริง** ในรุ่นที่คุณใช้
จึงไม่มีความเสี่ยงจากชื่อคำสั่งที่ต่างรุ่น

จากนั้นรันซ้ำแบบไม่ต้องใช้ GUI ได้ด้วย

```text
File > Run Script...  เลือก ps_build.tcl
```

หรือจากบรรทัดคำสั่ง

```bash
ps_shell -f ps_build.tcl
```

> *(ตรวจสอบกับเอกสารของรุ่นที่ใช้ว่าชื่อโปรแกรมและตัวเลือกเรียกสคริปต์เป็นอย่างไร
> PS2018.1 ใช้ `ps_shell` ในขณะที่รุ่นที่เก่ากว่าเรียก precision ด้วย `-shell`)*

### 2.7.3 สคริปต์ที่คู่มือเตรียมให้

ไฟล์ `labs/precision/ps_build.tcl` เขียนตามลำดับงาน PS2018.1 พอดี โดยมีคอมเมนต์
บอกคู่ขั้นตอนใน GUI และตัวแปรที่แก้ได้ที่บรรทัดเดียว

```tcl
set design_name "top_alu8"
set rtl_dir     "../rtl"
set sdc_file    "../sdc/top_alu8.sdc"
set out_dir     "out_10ns"

new_project $design_name -force -output $out_dir

add_input_file $rtl_dir/alu8.vhd      -vhdl
add_input_file $rtl_dir/hex2seg.vhd   -vhdl
add_input_file $rtl_dir/top_alu8.vhd  -vhdl

setup_design -manufacturer xilinx artix7 -part xc7a100tcsg324 -speed -1

read_sdc $sdc_file
report_timing -unconstrained_paths

compile
synthesize

report_timing -max_paths 20       > $out_dir/timing.rpt
report_timing -unconstrained_paths > $out_dir/unconstrained.rpt
report_area                       > $out_dir/area.rpt

write_edif $out_dir/$design_name.edif
write_sdc  $out_dir/$design_name.sdc
```

## 2.9 สรุปบท

- ลำดับของ PS2018.1 คือ สร้างโปรเจกต์ → เพิ่มไฟล์ (VHDL/Verilog/EDIF/SDC) → เลือกอุปกรณ์ → ตั้งความถี่ → Compile → Synthesize
- การเลือก part ทำให้ได้ตัวเลขจากไลบรารีเซลล์จริง ซึ่งเป็นพื้นฐานของการตัดสินใจเรื่อง QoR
- การใส่ SDC ครบถ้วนเป็นเงื่อนไขต้องของการวิเคราะห์ ถ้าไม่ใส่ PS จะไม่รายงานอะไรที่มีความหมาย
- สคริปต์ที่ได้จาก `File > Save Command File` คือสคริปต์ที่ถูกต้องกับรุ่นที่ใช้เสมอ

**เตรียมตัวก่อนบทถัดไป**: มีรายงานเวลาและพื้นที่จากการสังเคราะห์รอบแรก (บทที่ 3)
