ภาคนำ

คู่มือนี้คืออะไร

คู่มือนี้สอน การจำลองระดับ gate (Gate-Level Simulation, GLS) ด้วย QuestaSim ตั้งแต่พื้นฐานจนถึงระดับที่เอาไปใช้ต่อในงานจริงได้ แยกเป็น 8 lab แบบทีละขั้น ที่ทำตามแล้วรันได้จริงทุกขั้น

จุดต่างของคู่มือนี้คือ ตัวเลขและข้อความทุกตัวมาจากการรันจริงบนเครื่อง ไม่ใช่ตัวอย่างที่แต่งขึ้น — ทำซ้ำตามคู่มือแล้วจะได้ผลชุดเดียวกัน

ผู้เรียนจะได้อะไร

เมื่อทำครบทุก lab ผู้เรียนจะทำสิ่งเหล่านี้ได้ด้วยตัวเอง

  1. อธิบายได้ว่า RTL simulation กับ gate level simulation ต่างกันอย่างไร และอะไรที่ gate level จับได้แต่ RTL จับไม่ได้
  2. สังเคราะห์ RTL เป็น gate netlist ด้วย Yosys + Liberty ของ IHP SG13G2
  3. จำลอง netlist นั้นใน QuestaSim โดยใช้ testbench ชุดเดียวกับกับกับระดับ RTL
  4. อ่าน เซลล์มาตรฐาน ของ SG13G2 และเข้าใจว่า Liberty, Verilog model และ timing check ของแต่ละเซลล์เป็นอย่างไร
  5. จับ บั๊กใน netlist ที่การจำลองระดับ RTL มองไม่เห็น
  6. สร้าง regression ของการจำลองระดับ gate ที่รันซ้ำได้และรหัสจบนำไปใช้กับ CI ได้

1.2 ⚠ เรื่องใบอนุญาต (license) — อ่านให้เข้าใจก่อนทำ lab

only one session is allowed to run on an uncounted nodelocked
license and an instance of QuestaSim is already running with a
nodelocked license on this machine.

แต่ ModelSim DE-64 ยังรันได้ตามปกติ เพราะเป็นอีก seat หนึ่ง

ทางแก้ที่คู่มือนี้ใช้: ไม่ hardcode path ของชุดติดตั้งเลย แต่ให้ tools/pick_tool.cmd ไล่ทดสอบ license จริงของแต่ละชุด (คอมไพล์ design จิ๋วแล้วโหลดจริง — เพราะ license ถูกเช็คตอน “โหลด design” เท่านั้น) แล้วเลือกชุดแรกที่ใช้ได้

1.4 RTL กับ gate level ต่างกันอย่างไร

สิ่งที่จำลอง พฤติกรรมที่เขียนไว้ (always @(posedge clk)) โครงสร้างจริงของวงจร (transistor → gate → cell)

ขนาด เล็ก ใหญ่กว่ามาก (นับจาก 11 เซลล์ ถึงหลายพัน)

LAB 01 — เส้นฐาน: จำลอง RTL ที่เป็นจุดอ้างอิง

เป้าหมาย

ดูโค้ดของ DUT

module cnt4 (
    input  wire       clk,
    input  wire       rst_n,     // asynchronous, active low
    input  wire       en,
    output reg  [3:0] q
);

  always @(posedge clk or negedge rst_n) begin
    if (!rst_n)      q <= 4'd0;   // asynchronous reset
    else if (en)     q <= q + 4'd1;
  end

endmodule

2. เทียบ trace ทีละบรรทัดด้วย gls_diff_lines

proc gls_diff_lines {file_a file_b} {
    set a [split [gls_read_file $file_a] "\n"]
    set b [split [gls_read_file $file_b] "\n"]
    set diff {}
    set n [expr {[llength $a] > [llength $b] ? [llength $a] : [llength $b]}]
    for {set i 0} {$i < $n} {incr i} {
        set la [lindex $a $i]
        set lb [lindex $b $i]
        if {$la ne $lb} { lappend diff [list $i $la $lb] }
    }
    return $diff
}

2. อย่าใช้ != หรือ == ตรวจค่าที่อาจเป็น x

โดยปกติ vsim -c จบ session ทันทีที่ testbench เรียก $finish คำสั่งที่เหลือใน -do "..." ไม่ถูก execute เลย (เคยเจอกับ coverage save ที่ไม่มี error แต่ไฟล์ไม่ถูกสร้าง)

แก้โดยใส่ -onfinish stop

vsim -c -onfinish stop -do "do run_batch.do"

ก.4 vsim คืน exit code 0 เสมอ

แม้จะเปิดไฟล์ .do ไม่ได้เลย vsim ก็ยังคืน 0 ห้ามใช้ exit code ของ vsim เป็นเกณฑ์ PASS/FAIL

ทางเลือกที่ใช้ได้คือให้ testbench เขียนไฟล์ผลลัพธ์เอง แล้วให้ .cmd อ่านไฟล์นั้น

if not exist "result.txt" (
    echo [RESULT] FAIL -- the simulator did not finish
    exit /b 1
)
set /p RESULT=<result.txt
if /i "%RESULT%"=="PASS" ( exit /b 0 )
exit /b 1

ก.5 < redirection ใช้ไม่ได้ใน for block ของ .cmd

for %%D in (alu4 fsm_light sr16) do (
    set /p R=<results\%%D_verdict.txt>      rem <<< ทำให้ทั้ง block พังแบบเงียบ
)

ต้องใช้ for /f แทน

set "R="
for /f "usebackq delims=" %%V in ("results\%%D_verdict.txt") do set "R=%%V"

ก.6 [info script] ทำให้ตัวจำลอง crash

ใน ModelSim 2026.1 คำสั่ง [info script] คืนค่าเป็น พาธของตัว vsim เอง ไม่ใช่พาธของสคริปต์ และเมื่อนำไปใช้กับ file join แล้วเปิดไฟล์ ตัวจำลองจะ ล้มแล้วปิดตัวทันที

แก้โดยคำนวณพาธจาก [pwd] แทน

proc gls_root {} {
    return [file normalize [file join [pwd] ..]]
}

ก.7 $value$plusargs("%s") ตัดพาธที่ยาวเกิน 64 ตัวอักษร

ตัวแปรที่รับค่าจาก plusarg ต้องประกาศให้ยาวพอ

reg [8*64:1] tracefile = "trace.txt";

8*64 = 512 บิต = 64 ตัวอักษร ถ้าพาธยาวเกินนั้นจะถูกตัดทิ้ง (ซึ่งทำให้ $fopen ล้มเหลวแบบเงียบ ๆ)

ทางแก้คือใช้พาธแบบสัมพัทธ์สั้น ๆ เสมอ เช่น results/trace_rtl.txt ไม่ใช้พาธเต็มยาว ๆ

ก.8 void' เป็น SystemVerilog — vlog ธรรมดาใช้ไม่ได้

vlog (Verilog) รับเฉพาะ Verilog-2001 ถ้าเขียน void'(expr) หรือ bit/logic/always_ff จะคอมไพล์ไม่ผ่าน ต้องใช้ vlog -sv ซึ่งในโปรเจกต์นี้ ไม่ได้ใช้ เพื่อให้ flow ตรงกับ netlist ที่ Yosys สร้าง

ก.9 [ ใน string ที่ครอบด้วย " ใน Tcl จะเริ่ม command substitution

puts "   the trace has [llength $a] lines"      # <<< OK : [] ใน string ปกติ

แต่ถ้า string ถูกครอบด้วย " ภายใน {} หรืออยู่ในนิพจน์ที่ Tcl parse ใหม่ [ จะถูกตีความว่าเป็นการเรียก sub-command

วิธีหลีกเลี่ยงคือ escape ด้วย backslash หรือใช้ { } ครอบ

puts {   the trace has [llength $a] lines}

ก.10 timescale ของ testbench ต้องตรงกับของเซลล์

เซลล์ SG13G2 ประกาศ `timescale 1ns/10ps ถ้า testbench ประกาศ 1ns/1ns ความละเอียดเวลาจะไม่ตรงกัน และ $realtime จะให้ค่าที่ดูแปลก

ในโปรเจกต์นี้ testbench ทุกไฟล์ประกาศ `timescale 1ns/10ps เหมือนกันหมด

ก.11 $time ให้หน่วยเวลาไม่ใช่หน่วยเวลาของโมดูล

$time คืนจำนวนเต็มในหน่วย ความละเอียดเวลาของตัวจำลอง (ค่า default คือ 10 ps) $realtime คืนค่าเป็น real ในหน่วยเวลาของโมดูล

t=16 ns จะพิมพ์เป็น
$time 1600
$realtime 16.000

ก.12 ตัวตรวจต้องใช้ !== ไม่ใช่ !=

if (got !== exp) begin ... end

!= จะให้ผลเป็น false เมื่อค่าใดค่าหนึ่งเป็น x ทำให้บั๊กที่มีค่า x หลุดลอดออกไปโดยไม่มีใครรู้ตัว (ดูหลักฐานจริงใน LAB 06 และ LAB 07)

ก.13 ห้าม hardcode path ของชุดติดตั้ง

ใบอนุญาตเป็น node-locked แบบ session เดียว ถ้ามี QuestaSim GUI เปิดค้างอยู่ การรันแบบบรรทัดคำสั่งด้วยชุดนั้นจะถูกปฏิเสธ

คู่มือนี้จึงให้ใช้ tools/pick_tool.cmd ที่ไล่ทดสอบ license จริงของแต่ละชุด แล้วเลือกชุดแรกที่ใช้ได้

ก.14 ไฟล์ .cmd ต้องเป็น ASCII ล้วน

ถ้ามีข้อความภาษาไทยหรือ UTF-8 ในไฟล์ .cmd cmd.exe จะอ่านโครงสร้างบรรทัดผิด อาการที่เห็นบ่อยคือ บรรทัดคอมเมนต์กินอักขระแรกของบรรทัดถัดไปไป (echo กลายเป็น cho)

ในโปรเจกต์นี้ไฟล์ .cmd ทั้งหมดเป็น ASCII ล้วน ๆ ส่วนคำอธิบายภาษาไทยอยู่ในไฟล์ .md และคอมเมนต์ใน .do ซึ่งไม่มีข้อจำกัดนี้

ก.15 ABC ข้ามเซลล์ sequential และเซลล์ที่อยู่ใน dont_use

abc ทำงานเฉพาะ logic combinational log จะขึ้นว่า

Scl_LibertyReadGenlib() skipped sequential cell "sg13g2_dfrbp_1"

และเซลล์ที่ตั้ง dont_use ใน Liberty (เช่น antennanp, decap_4, decap_8) ก็จะไม่ถูกเลือกมาใช้

นี่คือเหตุผลที่ dfflibmap ต้องมาก่อน abc เสมอ

ก.16 Yosys fsm เปลี่ยน FSM binary เป็น one-hot

Yosys 0.52 แปลง FSM แบบ binary เป็น one-hot โดยอัตโนมัติ จึงทำให้ จำนวน flip-flop ใน netlist มากกว่าที่คาดจาก RTL

ตัวเลขจำนวน flip-flop ที่ได้จึง ขึ้นกับ flow ที่ใช้ ต้องระบุเสมอว่าได้จาก synth แบบไหน

ถ้าต้องการคุมรูปแบบเอง ให้ใช้ fsm -norecode หรือเขียน FSM เป็น one-hot ตั้งแต่ RTL

ก.17 dfflibmap ไม่ได้ map latch — และ write_verilog จะเขียน flip-flop กลับเป็น always

นี่คือข้อค้นพบที่วัดได้จริงจากการทำแบบฝึกหัด

1. ถ้าไม่มี dfflibmap

สถิติจาก Yosys จะขึ้นว่า flip-flop เป็นเซลล์ภายใน

   Number of cells:                 10
     $_DFFE_PN0P_                    4
     sg13g2_a21o_1                   1
     ...

แต่เมื่อเขียนไฟล์ Verilog ออกมา write_verilog จะ แปลงกลับ flip-flop เหล่านั้นเป็น always block เชิงพฤติกรรม

  always @(posedge clk, negedge rst_n)
    if (!rst_n) q[0] <= 1'h0;
    else if (en) q[0] <= _02_;

ผลคือ netlist ที่ได้ ยังคอมไพล์และจำลองผ่าน แต่ส่วน sequential ไม่ใช่ gate level เลย และตรรกะ combinational ก็เปลี่ยนไปด้วย เพราะ ABC optimize ได้ผลต่างออกไป

2. dfflibmap ไม่ได้จัดการ latch

แม้ชุดเซลล์ SG13G2 จะมีเซลล์ latch อยู่จริง (sg13g2_dlhq_1, sg13g2_dlhr_1 เป็นต้น) แต่ dfflibmap จัดการเฉพาะ flip-flop ถ้า RTL เขียนด้วย always @* แล้วสังเคราะห์ จะได้

   Number of cells:                 13
     $_DLATCH_N_                     4
     sg13g2_a21o_1                   1
     ...

และ netlist จะมี always @* เช่นกัน

  always @*
    if (!_04_) q[0] = _00_;

สรุป

ถ้าอยากให้ GLS ทดสอบอะไรจริง ๆ ต้องแน่ใจว่า ทุกเซลล์ใน netlist เป็นเซลล์มาตรฐานของ PDK ไม่ใช่เซลล์ภายในของ Yosys วิธีตรวจง่าย ๆ คือเปิดไฟล์ netlist แล้วดูว่า มี always block หลงเหลืออยู่หรือไม่ ถ้ามี แปลว่ายังไม่ใช่ gate level จริง

ก.18 ชื่อไฟล์ trace ที่ใช้ซ้ำกันทำให้การเทียบไร้ผล

วัดได้จริง: ถ้าให้ทั้งสองระดับเขียน trace ลงไฟล์เดียวกัน การรัน GLS จะ เขียนทับ trace ของ RTL ทิ้ง

ก่อนเขียนทับ (RTL) : 0, 1, 2, 3, 4, 5, 6, 6, 9
หลังเขียนทับ (GLS) : 0, 8, 9, 3, 4, c, d, d, 2

ถ้าสคริปต์เปรียบเทียบไฟล์กับตัวเอง จะได้ผลว่า เหมือนกัน 0 จุด ทั้งที่วงจรต่างกันสิ้นเชิง — เป็นกับดักที่ทำให้ GLS ไม่จับบั๊กเลย

แก้โดยใช้ชื่อไฟล์ต่างกันเสมอ (trace_rtl.txt / trace_gls.txt) ซึ่งเป็นสิ่งที่ LAB 05 ทำอยู่แล้ว

จ.2 ต่อยอดจากคู่มือนี้

คู่มือนี้ครอบคลุม พื้นฐานของ GLS เท่านั้น ถ้าจะเอาไปใช้กับงานจริง ขั้นต่อไปตามลำดับความยากคือ

  1. ใส่ SDF เพื่อดูความหน่วงจริง ตอนนี้โมเดล SG13G2 ใส่ค่าหน่วงเป็น 0 ใน specify block การจำลองจึงเห็นเวลาเป็นศูนย์หน่วง เมื่อมี SDF จะเห็น setup/hold violation และเวลาหน่วงจริงของแต่ละเซลล์

  2. ทำ netlist coverage เพิ่มคำสั่ง coverage ของ QuestaSim เพื่อวัดว่าเซลล์และเส้นทางใด ของ netlist ถูกกระตุ้นบ้าง รวมถึง toggle coverage ของ flip-flop

  3. ทำ X-propagation analysis LAB 06 สาธิตว่าค่า x แพร่ผ่านเกตได้ ใน flow จริงต้องมีการตรวจว่ามี x หลุดออกมาที่ output หรือไม่ (เครื่องมือที่นิยมคือ Questa X-prop / Synopsys VCZ)

  4. เปรียบเทียบกับ STA ผลของ GLS ควรตรงกับ static timing analysis ถ้าไม่ตรง แปลว่ามีปัญหาที่ระดับ setup/hold ที่การจำลองแบบไม่มี SDF จะไม่เห็น
