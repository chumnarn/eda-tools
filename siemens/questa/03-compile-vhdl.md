## 1. คำสั่ง `vcom`

```bash
vcom -2008 -work work src/counter_tut.vhd
```

| ส่วน | ความหมาย |
|---|---|
| `vcom` | คำสั่งคอมไพล์ VHDL |
| `-2008` | มาตรฐาน VHDL ที่ใช้ (ดูหัวข้อ 2) |
| `-work work` | ไลบรารีปลายทางของ design unit ที่คอมไพล์ |
| `src/counter_tut.vhd` | ไฟล์ที่จะคอมไพล์ |

### 1.1 ตัวเลือกที่ใช้บ่อย

| ตัวเลือก | ความหมาย |
|---|---|
| `-work <ชื่อ>` | ไลบรารีปลายทาง (ค่าเริ่มต้นคือ `work`) |
| `-93` `-2002` `-2008` `-2019` | มาตรฐาน VHDL |
| `-quiet` | ไม่พิมพ์ข้อความระหว่างคอมไพล์ |
| `-messages <ข้อความ>` | กรองประเภทข้อความที่แสดง เช่น `none` `error` `warning` |
| `-explicit` | ใช้ชื่อ library ที่ระบุใน context clause เท่านั้น ไม่มองหา library อื่น |
| `-check_synthesis` | ตรวจว่าโค้ดอยู่ใน synthesis subset |

### 1.2 ดูความช่วยเหลือ

```bash
vcom -help
```

> รายการตัวเลือกที่รองรับขึ้นกับรุ่นของเครื่องมือ
> ให้ใช้ผลของ `vcom -help` ของเครื่องที่ใช้จริงเป็นหลัก

## 2. มาตรฐาน VHDL ที่ต้องเลือกให้ถูก

### 2.1 สวิตช์ของมาตรฐาน

| สวิตช์ | มาตรฐาน | หมายเหตุ |
|---|---|---|
| `-93` | VHDL-1993 | มาตรฐานแรก ใช้ได้ทุกที่ |
| `-2000` | VHDL-2000 | รองรับ `std_logic_arith` เป็นมาตรฐาน |
| `-2002` | VHDL-2002 | มาตรฐานที่ห้องเรียนใช้ |
| `-2008` | VHDL-2008 | มาตรฐานหลักของไฟล์ใหม่ในคอร์สนี้ |
| `-2019` | VHDL-2019 | ต้องใช้เครื่องมือรุ่นที่รองรับ |

### 2.2 ค่าเริ่มต้นมาจากไฟล์ `.ini`

ถ้าไม่ระบุสวิตช์ คอมไพลเลอร์จะใช้ค่าจากคีย์ `VHDL93` ในไฟล์ตั้งค่า

```ini
[VHDL]
VHDL93 = "2002"
```

นี่คือเหตุผลที่โค้ดเดียวกันคอมไพล์ผ่านบนเครื่องหนึ่งแต่พังบนอีกเครื่อง
ถ้าเครื่องของคุณตั้งค่าไว้คนละค่า ให้ระบุสวิตช์ชัดเจนทุกครั้ง
เพื่อไม่ให้ผลขึ้นกับการตั้งค่าของแต่ละเครื่อง

### 2.3 กฎของคอร์สนี้

> ไฟล์ VHDL ที่เขียนใหม่ต้องใช้มาตรฐาน **VHDL-2008** เป็นหลัก
> แต่ต้องคอมไพล์ผ่าน **VHDL-2002** ด้วย
> เพราะ ModelSim/Questa ของห้องเรียนตั้งค่า `VHDL93 = 2002`

เหตุผลคือ ถ้าคอมไพล์ได้เฉพาะ VHDL-2008
นักศึกษาที่ใช้เครื่องมือของห้องเรียนจะรันโค้ดไม่ได้เลย

ฟีเจอร์ของ VHDL-2008 ที่ **ห้ามใช้** ในไฟล์ของคอร์สนี้

| ฟีเจอร์ | เหตุผล |
|---|---|
| `process (all)` | ไม่มีใน VHDL-2002 ต้องเขียน sensitivity list ให้ครบ |
| `std.env.stop` `std.env.finish` | เป็นแพ็กเกจของ VHDL-2008 ใช้ `assert ... severity failure` แทน |
| `to_hstring` | เป็นฟังก์ชันของ VHDL-2008 |
| conditional signal assignment ใน process | เป็นฟีเจอร์ของ VHDL-2008 เฉพาะในรูปแบบ sequential |
| `ieee.std_logic_textio` | เป็นแพ็กเกจของ VHDL-2008 ใช้ `std.textio` แทน |

> **หมายเหตุเรื่อง bit string literal — ไม่ใช่ฟีเจอร์เฉพาะ VHDL-2008**
>
> `x"FF"` `o"777"` `b"1010"` เป็น *bit string literal* ที่มีมาตั้งแต่ **VHDL-93**
> ไม่ใช่ของ VHDL-2008 วัดได้ด้วย GHDL 1.0.0 ว่าใช้ได้ทั้ง `--std=93` `--std=02` และ `--std=08`
>
> โค้ดของคอร์สนี้ยังไม่ใช้ เพราะเหตุผลที่ถูกต้องกว่า:
> **ความยาวของ literal นับเป็นจำนวนบิต ไม่ใช่จำนวนหลัก**
> `x"F"` จึงเป็น 4 บิต ไม่ใช่ 1 บิต และ `o"777"` เป็น 9 บิต ไม่ใช่ 3 บิต
> ให้ใช้ string literal `"11111111"` หรือ `std_logic_vector(to_unsigned(255, 8))` แทน
> เพื่อให้ความยาวชัดเจนโดยไม่ต้องเดา

## 3. ลำดับการคอมไพล์

### 3.1 กฎเหล็ก

> **package ต้องคอมไพล์ก่อนไฟล์ที่เรียกใช้มันเสมอ**

เครื่องมือคอมไพล์แต่ละไฟล์แยกจากกัน
ไฟล์ที่เรียกใช้ package จะคอมไพล์ผ่านก็ต่อเมื่อ package อยู่ในไลบรารีแล้ว

ลำดับที่ถูกต้อง

```bash
vcom -2008 -work work src/rom_pkg.vhd     # package ก่อน
vcom -2008 -work work src/rom.vhd         # แล้วจึงเป็นผู้ใช้ package
vcom -2008 -work work tb/tb_rom.vhd
```

### 3.2 ลำดับของ design unit ในไฟล์เดียว

ภายในไฟล์เดียวกัน เครื่องมือจะคอมไพล์ตามลำดับที่ปรากฏในไฟล์
โดยค่าเริ่มต้นของแต่ละ architecture คือ architecture ที่เพิ่งคอมไพล์ล่าสุด
ถ้าต้องการระบุเองให้เขียน

```vhdl
architecture rtl of counter_tut is
```

### 3.3 การคอมไพล์แบบเดียวกับที่สคริปต์ใช้

สคริปต์ `scripts/check_example.sh` ในชุดตัวอย่างคอมไพล์ไฟล์ที่มีชื่อลงท้ายด้วย
`_pkg.vhd` ก่อนเสมอ เพื่อไม่ให้ผลขึ้นกับลำดับที่ระบบไฟล์คืนมา

## 4. context clause

### 4.1 กฎของ VHDL

context clause มีผลกับ **design unit ถัดไปหนึ่งหน่วยเท่านั้น**

ดังนั้นไฟล์ที่มีทั้ง entity และ architecture ต้องประกาศ context clause สองครั้ง

```vhdl
library ieee;
use ieee.std_logic_1164.all;
use ieee.numeric_std.all;

entity counter_tut is
  ...
end entity counter_tut;

library ieee;
use ieee.std_logic_1164.all;
use ieee.numeric_std.all;

architecture rtl of counter_tut is
  ...
end architecture rtl;
```

### 4.2 เหตุผล

เพราะ context clause มีผลแค่หนึ่งหน่วย การประกาศไว้ที่บนสุดของไฟล์เพียงครั้งเดียว
จะทำให้ architecture ไม่เห็น `std_logic` และขึ้นข้อความ

```text
Unknown identifier "std_logic"
```

> นี่คือข้อผิดพลาดที่พบบ่อยที่สุดของผู้เรียน VHDL คนใหม่
> และเป็นข้อผิดพลาดที่คอร์สนี้ระบุไว้ใน `STYLE-GUIDE.md` ว่าห้ามให้เกิดซ้ำ

### 4.3 การอ้างอิงไลบรารีอื่น

```vhdl
library work;
use work.rom_pkg.all;

library vendor_lib;
use vendor_lib.cell_models.all;
```

ถ้า `vcom` หาไลบรารี `vendor_lib` ไม่พบจะรายงานข้อผิดพลาด
ตรวจด้วย `vmap` ว่าผูกไว้แล้วหรือยัง

## 5. การคอมไพล์หลายไฟล์และการคอมไพล์ซ้ำ

### 5.1 คอมไพล์ทีละไฟล์

```bash
vcom -2008 -work work src/counter_tut.vhd
vcom -2008 -work work tb/tb_counter_tut.vhd
```

คำสั่ง `vcom` รับไฟล์ได้หลายไฟล์ในคำสั่งเดียว

```bash
vcom -2008 -work work src/*.vhd tb/*.vhd
```

> **ห้ามใช้แบบนี้กับไฟล์ที่มี package** เพราะลำดับที่ glob คืนมาอาจผิด
> ให้คอมไพล์ไฟล์ `*_pkg.vhd` แยกออกมาก่อนเสมอ

### 5.2 การคอมไพล์ซ้ำแบบ incremental

เมื่อคอมไพล์ไฟล์เดิมซ้ำโดยไม่แก้ไข เครื่องมือจะขึ้นว่า

```text
** Error: (vcom-19) Failed to access library "work" at "work".
```

หรือขึ้นว่าไฟล์ไม่ได้ถูกแก้ไขจึงข้ามการคอมไพล์
การแก้ไขคือให้คอมไพล์ใหม่เสมอเมื่อแก้ไฟล์ และลบไลบรารีเมื่อต้องการเริ่มต้นใหม่

```bash
vdel -all -lib work      # ลบ design unit ทั้งหมดในไลบรารี
vdel counter_tut -lib work
```

### 5.3 ล้างไลบรารีก่อนรัน

```bash
rm -rf work && vlib work && vmap work work
```

บน Windows ใช้ `Remove-Item -Recurse -Force work` แทน
หรือใช้ `vdel -all -lib work` ซึ่งปลอดภัยกว่า

> สคริปต์ `scripts/questa_run.sh` ในชุดตัวอย่างลบไลบรารีของแต่ละตัวอย่าง
> ก่อนรันทุกครั้ง เพื่อให้ผลไม่ขึ้นกับของที่ค้างอยู่

## 6. ข้อผิดพลาดที่พบบ่อยตอนคอมไพล์ VHDL

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| `Unknown identifier "std_logic"` | context clause ครอบคลุมแค่ design unit เดียว | ประกาศ `library`/`use` ซ้ำก่อนทุก `entity` และทุก `architecture` |
| `String literal has a character with value 0x84` | มีอักขระไทยใน `report "..."` | ข้อความใน string literal ต้องเป็น ASCII ภาษาไทยใช้ได้เฉพาะในคอมเมนต์ |
| `Unable to bind to entity "xxx"` หรือ `unit "xxx" not found` | คอมไพล์ยังไม่ครบ หรือผูกไลบรารีผิดพาธ | คอมไพล์ให้ครบตามลำดับ แล้วตรวจด้วย `vmap` |
| `package "xxx" not found` | คอมไพล์ไฟล์ที่ใช้ package ก่อนคอมไพล์ package | คอมไพล์ `*_pkg.vhd` ก่อนเสมอ |
| `Operator "+" is not defined for type "STD_LOGIC_VECTOR"` | ไม่ได้ `use ieee.numeric_std.all` | เพิ่ม `use ieee.numeric_std.all;` ห้ามใช้ `std_logic_arith` |
| `cannot be assigned to "OUT" port` หรือข้อความคล้ายกัน | พอร์ต `out` อ่านค่าก่อนเขียนได้ | ใช้ `inout` หรืออ่านผ่าน signal ภายในโมดูล |
| ข้อความบอกว่าฟีเจอร์ไม่รองรับเมื่อใช้ `-2002` | ใช้ฟีเจอร์ของ VHDL-2008 | ดูตารางฟีเจอร์ที่ห้ามใช้ในหัวข้อ 2.3 |
| `(vcom-34) Signal "xxx" has multiple drivers` | มี process หรือ concurrent assignment ขับสัญญาณเดียวกันสองที่ | ตรวจว่ามีการ assign สัญญาณนั้นซ้ำหรือไม่ |
| คอมไพล์ผ่านแต่รันแล้วค่าเป็น X | สัญญาณไม่มี driver หรืออ่านค่าก่อนถึงเวลา | เพิ่ม `wait for 1 ns` หลังชนิดขอบเขต และตรวจ reset |

> ข้อความที่เจอจริงอาจต่างจากตารางนี้เล็กน้อยตามรุ่นของเครื่องมือ
> ให้ดูเลขข้อผิดพลาดที่ท้ายข้อความ เช่น `(vcom-19)`
> แล้วค้นหาคำอธิบายในเอกสาร ModelSim/Questa User's Manual

## แบบฝึกหัดท้ายบท

1. คอมไพล์ `ex00_counter_tutorial` ด้วย `-2008` แล้วสังเกตข้อความที่เครื่องมือพิมพ์
2. คอมไพล์ซ้ำด้วย `-2002` แล้วเทียบข้อความทั้งสองครั้ง
3. จงให้ context clause ของ architecture หายไป แล้วคอมไพล์ซ้ำ
   จากนั้นบันทึกข้อความที่ได้ แล้วแก้กลับ
4. คอมไพล์ไฟล์ `tb/tb_counter_tut.vhd` ก่อน แล้วคอมไพล์ `src/counter_tut.vhd`
   จากนั้นลองรันและบันทึกข้อความที่ได้ แล้วคอมไพล์ใหม่ตามลำดับที่ถูกต้อง
5. สร้างไฟล์ VHDL ขนาดเล็กที่มี `report "ทดสอบ"` แล้วคอมไพล์
   จากนั้นเปลี่ยนเป็น `report "ทดสอบ"` ที่มีอักขระไทย แล้วคอมไพล์ซ้ำ

---

## คำถามท้ายบท

1. เหตุใดโค้ดที่คอมไพล์ผ่าน VHDL-2008 จึงอาจพังบนเครื่องของห้องเรียน
2. context clause มีผลกับ design unit กี่หน่วย และนั่นทำให้เกิดข้อผิดพลาดอะไร
3. ทำไมต้องคอมไพล์ package ก่อนไฟล์ที่เรียกใช้
4. ค่า `VHDL93` ในไฟล์ `.ini` ส่งผลต่อคำสั่งใด
5. รายการฟีเจอร์ VHDL-2008 ที่ห้ามใช้ในคอร์สนี้มีอะไรบ้าง เพราะอะไร
