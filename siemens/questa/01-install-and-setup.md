## 1. สิ่งที่ต้องมี

| สิ่งที่ต้องมี | ข้อกำหนด | หมายเหตุ |
|---|---|---|
| ระบบปฏิบัติการ | Windows, Linux หรือ macOS | รุ่น 64 บิตแนะนำ |
| ใบอนุญาต | ต้องมี license ที่ใช้งานได้ | มีทั้งแบบ standalone และแบบเครือข่าย (license server) |
| ดิสก์พื้นที่ | รุ่นที่ติดตั้งเต็มต้องการหลาย GB | รวมเอกสารและตัวอย่างในตัว |
| เครื่องมือเสริม | `ghdl` เป็นตัวเลือก | ใช้สำรองเมื่อไม่มี license ดู[บทที่ 11](11-ghdl-cross-reference.md) |

> หากยังไม่มี license ให้ใช้ **GHDL** ที่ติดตั้งฟรีแทนได้
> คำสั่งและโค้ดในคู่มือนี้เหมาะกับทั้งสองเครื่องมือ
> รายละเอียดความต่างอยู่ใน[บทที่ 11](11-ghdl-cross-reference.md)

## 2. ติดตั้งและใบอนุญาต

### 2.1 ขั้นตอนติดตั้ง

1. ดาวน์โหลดตัวติดตั้งจากหน้าเว็บไซต์ของ Siemens EDA
   (ต้องมีบัญชีผู้ใช้ที่ลงทะเบียนไว้)
2. เลือก edition ที่ต้องการ — รุ่นที่มี VHDL คือ Questa SIM หรือ ModelSim
   ไม่ใช่ Questa Intel FPGA / Questa One ที่เน้นการจำลองระบบดิจิทัล
3. ติดตั้งตามขั้นตอนของตัวติดตั้ง
4. ติดตั้งใบอนุญาตตามวิธีขององค์กร — เช่น ใส่ไฟล์ license ลงในโฟลเดอร์
   `license` หรือกำหนด `LM_LICENSE_FILE`

### 2.2 การตรวจใบอนุญาต

คำสั่ง `lmutil` ที่มาพร้อมเครื่องมือใช้ตรวจใบอนุญาตได้

```bash
lmutil lmstat -a
```

ผลที่ต้องเห็นคือรายการ feature ที่ใช้ได้ ถ้าไม่เห็นสักรายการแสดงว่า
ยังไม่มีใบอนุญาตที่เครื่องมือมองเห็น

> ถ้าเป็นเครื่องที่ใช้ในห้องเรียน ให้ตรวจสอบกับผู้ดูแลห้องเรียนว่า
> license server อยู่ที่ address ใด และมีการตั้งค่า
> `LM_LICENSE_FILE` หรือ `LM_LICENSE_SERVER` แล้วหรือยัง

## 3. ตั้งค่า PATH และตัวแปรสภาพแวดล้อม

### 3.1 ตัวแปรที่ต้องตั้ง

| ตัวแปร | ความหมาย | ต้องตั้งไหม |
|---|---|---|
| `PATH` | ต้องมีโฟลเดอร์ `bin` ของเครื่องมือ เพื่อเรียก `vsim` `vcom` `vlib` ได้ | **ต้อง** |
| `MODELSIM` | โฟลเดอร์ที่ติดตั้งเครื่องมือ ใช้หาไฟล์ตั้งค่าและตัวอย่าง | แนะนำ |
| `LM_LICENSE_FILE` | พาธของไฟล์ใบอนุญาต | เมื่อใช้ใบอนุญาตแบบไฟล์ |
| `LM_LICENSE_SERVER` | address ของ license server | เมื่อใช้ใบอนุญาตแบบเครือข่าย |

### 3.2 Windows

เพิ่มโฟลเดอร์ `bin` ลงใน `PATH` ผ่าน
**System Properties → Advanced → Environment Variables**

```text
ตัวอย่างพาธ: C:\intelFPGA_lite\23.1std\modeltech64_2023.1\win64
```

ตรวจว่าใช้งานได้ เปิด PowerShell แล้วรัน

```powershell
vsim -version
```

### 3.3 Linux และ WSL2

เพิ่มโฟลเดอร์ `bin` ลงใน `PATH` ผ่านไฟล์ `~/.bashrc` หรือ `~/.zshrc`

```bash
export MODELSIM=/opt/questa/sim/bin
export PATH="$MODELSIM:$PATH"
export LM_LICENSE_FILE=27000@license-server.campus
```

ทดสอบใหม่ทุกครั้ง

```bash
source ~/.bashrc
vsim -version
```

> ต้องระวังว่า WSL2 กับ Windows ใช้ใบอนุญาตคนละชุดกัน
> ใบอนุญาตที่ผูกกับ host name ของเครื่อง Windows อาจใช้ใน WSL2 ไม่ได้
> ให้ตรวจสอบกับผู้ดูแลระบบ

## 4. ไฟล์ตั้งค่า .ini

### 4.1 ต่างอย่างไรระหว่าง ModelSim กับ Questa

| เครื่องมือ | ชื่อไฟล์ตั้งค่า |
|---|---|
| ModelSim | `modelsim.ini` |
| Questa SIM | `questasim.ini` |

ทั้งสองไฟล์มีรูปแบบเดียวกัน คือรูปแบบ INI ของ Windows
ประกอบด้วยส่วน `[ชื่อส่วน]` และคู่ `คีย์ = ค่า`

### 4.2 ลำดับการค้นหาไฟล์ตั้งค่า

เครื่องมือจะอ่านไฟล์ตั้งค่าจาก **ไดเรกทอรีปัจจุบันก่อน**
แล้วจึงไปหาในโฟลเดอร์ที่ติดตั้ง

ข้อดีคือทำให้แต่ละโปรเจกต์มีค่าตั้งของตัวเองได้โดยไม่กระทบกัน
และหลีกเลี่ยงปัญหาโฟลเดอร์ติดตั้งเขียนไฟล์ไม่ได้

### 4.3 ตัวอย่างไฟล์ตั้งค่าขั้นต่ำ

สร้างไฟล์ `modelsim.ini` (หรือ `questasim.ini`) ในโฟลเดอร์ที่ทำงาน

```ini
; การผูกไลบรารีเชิงตรรกะกับตำแหน่งจริงบนดิสก์
[Library]
work = ./work

[VHDL]
; มาตรฐาน VHDL ที่ใช้เป็นค่าเริ่มต้นของคำสั่ง vcom
; ค่าที่ใช้ได้คือ 1993, 2000, 2002, 2019
VHDL93 = "2002"

; ไม่ให้คอมไพลเลอร์แทรก package ของ std_logic_arith ให้โดยอัตโนมัติ
; เพราะแพ็กเกจนี้ไม่อยู่ในมาตรฐานและมีพฤติกรรมกำกวม
StdArithNoPackage = 1
```

> ค่า `VHDL93 = "2002"` ตรงกับการตั้งค่าของห้องเรียนที่ใช้ใน Lab ของคอร์สนี้
> จึงทำให้ผลการคอมไพล์ในบทนี้ตรงกับผลในห้องเรียน

### 4.4 ค่าที่ควรรู้เพิ่มเติม

| คีย์ | ความหมาย | หมายเหตุ |
|---|---|---|
| `VHDL93` | มาตรฐาน VHDL เริ่มต้นของ `vcom` | ตรวจด้วยคำสั่ง `vcom -help` ว่ารุ่นที่ใช้รองรับค่าอะไรบ้าง |
| `StdArithNoPackage` | ไม่แทรก `std_logic_arith` อัตโนมัติ | แนะนำให้เป็น 1 |
| `BreakOnAssertionSeverity` | ระดับ severity ที่ทำให้ simulation หยุด | ชื่อคีย์และค่าที่รับได้อาจต่างกันตามรุ่น |

> รายชื่อคีย์ที่รองรับทั้งหมดของแต่ละรุ่นอยู่ใน
> ModelSim/Questa User's Manual หัวข้อ **INI File Variables**
> ให้เปิดไฟล์ `.ini` ของเครื่องที่ใช้อยู่เพื่อดูค่าจริงก่อนแก้

### 4.5 ผูกไลบรารีด้วย `vmap`

คำสั่ง `vmap` เขียนการผูกไลบรารีลงไฟล์ตั้งค่า

```bash
vmap work work
```

โครงสร้างของคำสั่งคือ `vmap <ชื่อโลจิคาล> <พาธจริง>`
เมื่อไม่ระบุพาธจริง จะถือว่าเป็นชื่อเดียวกันในไดเรกทอรีปัจจุบัน

ดูรายการที่ผูกไว้ทั้งหมดได้ด้วย

```bash
vmap
```

> ถ้า `vmap` ล้มเหลวเพราะโฟลเดอร์ติดตั้งเป็น read-only ให้สร้างไฟล์ `.ini`
> ในไดเรกทอรีที่ทำงานแทน ตามตัวอย่างในหัวข้อ 4.3

## 5. ตรวจว่าติดตั้งสำเร็จ

### 5.1 ตรวจเวอร์ชัน

```bash
vsim -version
```

ผลที่ต้องเห็นคือข้อความเวอร์ชันและหมายเลข build
ให้บันทึกไว้ เพราะพฤติกรรมของบางคำสั่งต่างกันระหว่างรุ่น

### 5.2 ตรวจความพร้อมของคำสั่งหลัก

```bash
vlib -help
vcom -help
vsim -help
```

ถ้าทั้งสามคำสั่งตอบกลับมาพร้อมรายการตัวเลือก แสดงว่า `PATH` ตั้งถูกต้องแล้ว

### 5.3 ตรวจว่าคอมไพล์ VHDL ได้จริง

ใช้ตัวอย่างที่เล็กที่สุด

```bash
cd code/reference/questa/examples/ex00_counter_tutorial
vlib work
vmap work work
vcom -2008 -work work src/counter_tut.vhd
vcom -2008 -work work tb/tb_counter_tut.vhd
vsim -c -work work -do "run -all; quit -f" tb_counter_tut
```

ผลที่ต้องเห็น

```text
... GOLDEN_COUNTER_TUT_PASS: 10 check(s) passed
```

ถ้าไม่เห็น ให้ดู[บทที่ 12 — ปัญหาที่พบบ่อย](12-troubleshooting.md)

## 6. ปัญหาที่พบบ่อยตอนติดตั้ง

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| `vsim` ไม่รู้จักคำสั่ง | `PATH` ไม่มีโฟลเดอร์ `bin` ของเครื่องมือ | เพิ่มโฟลเดอร์ลงใน `PATH` แล้วเปิดหน้าต่าง terminal ใหม่ |
| `license` หมดอายุ / ไม่พบ feature | ไม่มีใบอนุญาตที่มองเห็น | ตรวจด้วย `lmutil lmstat -a` และตั้ง `LM_LICENSE_FILE` หรือ `LM_LICENSE_SERVER` |
| `vmap` เขียนไฟล์ไม่ได้ | โฟลเดอร์ติดตั้งเป็น read-only | สร้างไฟล์ `.ini` ในไดเรกทอรีที่ทำงานตามหัวข้อ 4.3 |
| `vcom` คอมไพล์ผิดมาตรฐาน | `VHDL93` ในไฟล์ `.ini` ไม่ใช่ `2002` | ตรวจค่าในไฟล์ `.ini` หรือระบุชัดเจนด้วย `vcom -2002` |
| เปิด `vsim` แล้วไม่มีหน้าต่าง | รันอยู่ในโหมด command line ที่เคยสั่ง `-c` | ปิดแล้วเปิดใหม่โดยไม่ใส่ `-c` |
| ไฟล์ `.vhd` คอมไพล์ไม่ได้ | มี BOM ที่ต้นไฟล์ | ตรวจด้วย `Format-Hex <file> \| Select-Object -First 1` แล้วบันทึกใหม่แบบ UTF-8 without BOM |
| `String literal has a character with value 0x84` | มีอักขระไทยใน `report "..."` | ข้อความใน string literal ต้องเป็น ASCII ภาษาไทยใช้ได้เฉพาะในคอมเมนต์ |

## แบบฝึกหัดท้ายบท

1. ตั้ง `PATH` แล้วรัน `vsim -version` บันทึกเวอร์ชันและหมายเลข build
2. สร้างไฟล์ `modelsim.ini` หรือ `questasim.ini` ในไดเรกทอรี
   `code/reference/questa/examples/ex00_counter_tutorial/` ตามหัวข้อ 4.3
   แล้วตรวจด้วย `vmap` ว่าการผูกไลบรารีถูกต้อง
3. คอมไพล์และจำลอง `ex00_counter_tutorial` จนได้ marker
   `GOLDEN_COUNTER_TUT_PASS` แล้วบันทึกข้อความ Transcript ไว้
4. ลองเปลี่ยน `VHDL93` เป็น `"93"` แล้วคอมไพล์ซ้ำ สังเกตข้อความที่เปลี่ยนไป
   แล้วคืนค่ากลับเป็น `"2002"`
5. เปิดไฟล์ `.ini` ของเครื่องที่ใช้อยู่ บันทึกคีย์ทั้งหมดที่พบ
   แล้วเทียบกับตารางในหัวข้อ 4.4 ว่าต่างกันตรงไหน

---

## คำถามท้ายบท

1. เหตุใดเครื่องมือจึงอ่านไฟล์ `.ini` จากไดเรกทอรีปัจจุบันก่อน
2. ค่า `VHDL93` มีผลต่อคำสั่งใดโดยเฉพาะ และถ้าไม่ตั้งค่าไว้จะเกิดอะไร
3. `StdArithNoPackage` มีไว้ทำอะไร และเหตุใดคอร์สนี้จึงแนะนำให้เป็น 1
4. วิธีแก้ปัญหาที่ `vmap` เขียนไฟล์ไม่ได้โดยไม่ต้องขอสิทธิ์ผู้ดูแลระบบ
5. ทำไมต้องบันทึกเวอร์ชันของเครื่องมือไว้ทุกครั้งที่เริ่มโปรเจกต์ใหม่
