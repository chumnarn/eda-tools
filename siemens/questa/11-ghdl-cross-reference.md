# บทที่ 11: เทียบเทียบ GHDL กับ Questa SIM

> สองเครื่องมือนี้ทำงานคนละแบบในหลายจุด
> การรู้ความต่างช่วยไม่ให้เสียเวลาไปกับการเปรียบเทียบผลที่ไม่จำเป็น
> และช่วยให้เลือกเครื่องมือที่เหมาะกับงาน

**เครื่องมือที่เกี่ยวข้อง:** GHDL และ Questa SIM
**สถานะการทดสอบ:** ข้อมูลในบทนี้เป็นผลจากการรันจริงด้วย GHDL 1.0.0
บน WSL2 Ubuntu 22.04 ส่วนพฤติกรรมของ Questa ยังต้องให้ผู้เรียนตรวจสอบเอง

## 1. ทำไมต้องรู้ความต่าง

| เหตุผล | รายละเอียด |
|---|---|
| **ใช้ทดสอบโค้ดได้โดยไม่มี license** | GHDL เป็นซอฟต์แวร์ฟรี ใช้ตรวจว่าโค้ดคอมไพล์และทำงานถูกต้องก่อนส่งเข้า Questa |
| **ผลของ severity ต่างกัน** | ถ้าไม่รู้ จะตั้งเกณฑ์ CI ผิดและปล่อยให้บั๊กหลุด |
| **คำสั่งไม่เหมือนกัน** | สคริปต์ที่เขียนด้วย GHDL จะรันด้วย Questa ไม่ได้โดยตรง |
| **ความละเอียดเวลาต่างกัน** | ค่าเวลาที่แสดงใน log ของ GHDL อยู่ในหน่วย femtosecond |

## 2. ตารางคำสั่งเทียบเท่า

| งาน | Questa SIM | GHDL 1.0.0 |
|---|---|---|
| ตรวจเวอร์ชัน | `vsim -version` | `ghdl --version` |
| สร้าง working library | `vlib work` และ `vmap work work` | `ghdl -a --workdir=work <ไฟล์>` |
| ผูกไลบรารี | `vmap <ชื่อ> <พาธ>` | ใช้ `--workdir=` กำหนดตำแหน่งโดยตรง |
| คอมไพล์ | `vcom -2008 -work work f.vhd` | `ghdl -a --std=08 --workdir=work f.vhd` |
| ระบุมาตรฐาน | `vcom -2002 -work work f.vhd` | `ghdl -a --std=02 --workdir=work f.vhd` |
| สร้าง executable | ทำในขั้นตอน `vsim` | `ghdl -e --std=08 --workdir=work tb` |
| จำลอง | `vsim -c -work work -do "run -all; quit -f" tb` | `ghdl -r --std=08 --workdir=work tb` |
| จำลองแบบไม่หยุดที่ error | `severity error` หยุดตามการตั้งค่า | เพิ่ม `--assert-level=error` |
| รหัสออกเมื่อผิดพลาด | `quit -code 1` ใน `-do` | ได้จากการจบของ `ghdl -r` |
| สังเคราะห์เป็น netlist | `vopt` + `vsim` | `ghdl --synth --std=08 --workdir=work top` |
| บันทึก waveform | `vsim -wlf out.wlf` | `ghdl -r ... --wave=out.ghw` |
| บันทึก waveform รูปแบบ VCD | แปลงจาก WLF | `ghdl -r ... --vcd=out.vcd` |
| ดูรายการ design unit | `vdir work` | `ghdl --dir --std=08 --workdir=work` |
| ลบ design unit | `vdel -all -lib work` | ลบโฟลเดอร์ `--workdir` แล้วสร้างใหม่ |

### 2.1 ตัวอย่างคำสั่งที่เทียบกันได้ตรง ๆ

รันตัวอย่าง `ex00_counter_tutorial`

```bash
# Questa
vlib work
vmap work work
vcom -2008 -work work src/counter_tut.vhd
vcom -2008 -work work tb/tb_counter_tut.vhd
vsim -c -work work -do "onerror {quit -code 1}; onbreak {quit -code 1}; run -all; quit -code 0" work.tb_counter_tut
```

```bash
# GHDL
ghdl -a --std=08 --workdir=work src/counter_tut.vhd tb/tb_counter_tut.vhd
ghdl -e --std=08 --workdir=work tb_counter_tut
ghdl -r --std=08 --workdir=work tb_counter_tut --assert-level=error
```

### 2.2 ข้อสังเกตเรื่องไลบรารี

| | Questa | GHDL |
|---|---|---|
| ไลบรารีเป็นโฟลเดอร์ที่มี `_info` | ใช่ | ไม่ใช่ |
| ต้องผูกชื่อโลจิคาลกับพาธ | ใช่ (`vmap`) | ไม่ใช่ ใช้ `--workdir` แทน |
| คอมไพล์ซ้ำแบบ incremental | ได้ | ได้ |

> สคริปต์ `scripts/check_example.sh` ในชุดตัวอย่างใช้ `--workdir` ของ GHDL
> ส่วน `scripts/questa_run.sh` ใช้ `vlib`/`vmap`/`vcom`/`vsim`
> ทั้งสองสคริปต์ตรวจ marker `GOLDEN_<ชื่อ>_PASS` เหมือนกัน

## 3. มาตรฐาน VHDL

| มาตรฐาน | Questa | GHDL |
|---|---|---|
| VHDL-1993 | `vcom -93` | `ghdl -a --std=93` |
| VHDL-1993 แบบผ่อนคลายชุดอักขระ | — | `ghdl -a --std=93c` (ค่าเริ่มต้นของ GHDL) |
| VHDL-2002 | `vcom -2002` | `ghdl -a --std=02` |
| VHDL-2008 | `vcom -2008` | `ghdl -a --std=08` |
| VHDL-2019 | `vcom -2019` | ไม่รองรับใน 1.0.0 |

### 3.1 ความต่างที่พบจริง

| เรื่อง | Questa | GHDL 1.0.0 |
|---|---|---|
| ค่าเริ่มต้นของมาตรฐาน | อ่านจาก `VHDL93` ในไฟล์ `.ini` | ต้องระบุ `--std=` เสมอ ค่าเริ่มต้นคือ `93c` |
| `ieee.std_logic_textio` | ใช้ได้เมื่อคอมไพล์ด้วย `-2008` | ปฏิเสธในโหมด `--std=02` โดยให้ใช้ `-fsynopsys` |
| `std.env.stop` / `std.env.finish` | ใช้ได้เมื่อคอมไพล์ด้วย `-2008` | ใช้ได้เมื่อคอมไพล์ด้วย `--std=08` |
| literal แบบ `x"FF"` (bit string literal) | เป็นของ VHDL-93 ตามมาตรฐาน แต่ยังไม่ได้ตรวจสอบบน Questa ของห้องเรียน | ใช้ได้ทั้ง `--std=93` `--std=02` `--std=08` (วัดได้จริง) |
| อักขระภาษาไทยในคอมเมนต์ | ยังไม่ได้ตรวจสอบบน Questa ของห้องเรียน | `--std=93` เข้ม ปฏิเสธ แต่ `--std=93c` `--std=02` `--std=08` รับได้ (วัดได้จริง) |

> **ทำไมถึงต้องระบุ `--std=` เสมอ**
> ค่าเริ่มต้นของ GHDL คือ `93c` ไม่ใช่ `08`
> ถ้าปล่อยไว้โค้ดอาจคอมไพล์ผ่านด้วยกฎของ VHDL-93 แต่พังเมื่อเปลี่ยนไปใช้ `--std=08`
> ให้ระบุ `--std=08` หรือ `--std=02` เสมอในสคริปต์

> ข้อสรุปที่ใช้ได้ทั้งสองเครื่องมือ
> **ห้ามใช้ฟีเจอร์เฉพาะ VHDL-2008 ในโค้ดของคอร์สนี้**
> เพราะห้องเรียนตั้ง `VHDL93 = 2002`

## 4. พฤติกรรมของ severity

### 4.1 ผลที่วัดได้ด้วย GHDL 1.0.0

| severity | GHDL ค่าเริ่มต้น | GHDL กับ `--assert-level=error` | รหัสออก |
|---|---|---|---|
| `note` | พิมพ์แล้วจบปกติ | พิมพ์แล้วจบปกติ | 0 |
| `warning` | พิมพ์แล้วจบปกติ | พิมพ์แล้วจบปกติ | 0 |
| `error` | พิมพ์แล้ว **จบปกติ** | พิมพ์แล้ว **หยุด** | 0 หรือ 1 |
| `failure` | พิมพ์แล้ว **หยุด** | พิมพ์แล้ว **หยุด** | 1 |

### 4.2 ข้อควรระวัง

> ใน GHDL ค่าเริ่มต้นคือ **หยุดเฉพาะระดับ `failure`**
> ถ้าใช้ `--assert-level=error` จะหยุดที่ระดับ `error` ด้วย

คำสั่งที่ใช้วัดผล

```bash
ghdl -r --std=08 --workdir=work/ex03_assert_severity_08 tb_assert_severity \
     -gFAIL_MODE=true -gSEVERITY_LEVEL=2
```

ผลที่ได้คือพิมพ์ `(assertion error)` แล้วจบปกติด้วยรหัส 0
เมื่อเติม `--assert-level=error` จะหยุดและได้รหัส 1

### 4.3 พฤติกรรมของ Questa ยังต้องยืนยัน

ขั้นตอนยืนยันอยู่ใน[บทที่ 9](09-assertions-and-severity.md#32-สิ่งที่ต้องทำเองเพื่อยืนยันพฤติกรรมของ-questa)

### 4.4 ข้อสรุปที่ปลอดภัย

| ข้อสรุป | ใช้ได้ทั้งสองเครื่องมือ |
|---|---|
| `note` และ `warning` ไม่ทำให้ simulation หยุด | ใช่ |
| `failure` ทำให้ simulation หยุดและรหัสออกไม่ใช่ศูนย์ | ใช่ |
| `error` อาจหยุดหรือไม่หยุด | **ต้องทดลองด้วยตัวเอง** |

> เนื่องจากเหตุผลข้างบน สคริปต์ตรวจของคอร์สนี้จึงตรวจ **ทั้งรหัสออกและข้อความใน log**
> ไม่พึ่งพฤติกรรมของ severity อย่างเดียว

## 5. การบันทึก waveform

### 5.1 ผลที่วัดได้ด้วย GHDL 1.0.0

```bash
ghdl -r --std=08 --workdir=work/ex00_counter_tutorial_08 tb_counter_tut --wave=/tmp/tut.ghw
ghdl -r --std=08 --workdir=work/ex00_counter_tutorial_08 tb_counter_tut --vcd=/tmp/tut.vcd
```

ผลที่วัดได้

| รูปแบบ | ผล |
|---|---|
| `--wave=` (GHW) | สร้างไฟล์ได้ — วัดได้ 812 ไบต์สำหรับตัวอย่าง `ex00` |
| `--vcd=` (VCD) | สร้างไฟล์ได้ — วัดได้ 123 บรรทัดสำหรับตัวอย่าง `ex00` |

### 5.2 ข้อสังเกตเรื่องหน่วยเวลา

> ไฟล์ VCD ที่ GHDL สร้างมี `$timescale 1 fs`
> เวลาที่แสดงใน log ของ GHDL จึงอยู่ในหน่วย femtosecond
> เช่น `time'image(now)` ให้ `46000000 fs` แทนที่จะเป็น `46 ns`

การแปลงกลับ: `46000000 fs = 46 ns`

> ส่วน Questa ใช้หน่วยเวลาของ simulation ซึ่งปกติคือ `fs` เช่นกัน
> ค่า `46000000 fs` จึงเป็นค่าปกติ ไม่ใช่บั๊ก

### 5.3 รูปแบบไฟล์เทียบเท่า

| รูปแบบ | ใช้กับ |
|---|---|
| WLF | รูปแบบเฉพาะของ Questa เปิดดูได้ใน Questa และ ModelSim |
| VCD | มาตรฐานเปิด อ่านได้ด้วย GTKWave และเครื่องมืออื่น |
| GHW | รูปแบบของ GHDL เปิดดูได้ด้วย GTKWave |

## 6. เครื่องมือ debug

| ความสามารถ | Questa | GHDL |
|---|---|---|
| เปิดหน้าต่างกราฟิก | มี ครบทุกอย่าง | ไม่มี |
| ใช้ `ghdl --synth` ดู netlist | มี (`vopt`) | มี |
| ตั้ง breakpoint และ step | มี | ไม่มี |
| ดูค่าของสัญญาณระหว่างรัน | มี (`examine` `watch`) | ไม่มีแบบโต้ตอบ |
| บังคับค่าสัญญาณระหว่างรัน | มี (`force` `release`) | ไม่มี |
| เปรียบเทียบ waveform | มี | ไม่มี |
| PSL assertion | มี | มีบางส่วน |
| code coverage | มี | ไม่มี |

> **สรุปบทบาท:** GHDL เหมาะกับการตรวจว่าโค้ดถูกต้อง
> ส่วน Questa เหมาะกับการ debug เชิงลึก
> ทางเลือกที่ดีที่สุดคือใช้ทั้งสอง

## 7. แนวทางสำหรับห้องเรียน

### 7.1 ถ้ามี license ของ Questa

ใช้ Qesta เป็นเครื่องมือหลักในห้องเรียน
และใช้ GHDL เป็นตัวตรวจสอบเบื้องต้นในเครื่องส่วนตัวของนักศึกษา

### 7.2 ถ้าไม่มี license

ใช้ GHDL เป็นเครื่องมือหลัก
คำสั่งต่อไปนี้ใช้แทนกันได้

| ต้องการทำ | GHDL |
|---|---|
| คอมไพล์และจำลอง | `ghdl -a --std=08 --workdir=work ...` แล้ว `ghdl -r --std=08 --workdir=work tb` |
| บันทึก waveform | เติม `--wave=out.ghw` หรือ `--vcd=out.vcd` |
| เปิดดู waveform | ใช้ GTKWave เปิดไฟล์ `.ghw` หรือ `.vcd` |
| ตรวจว่าโค้ดสังเคราะห์ได้ | `ghdl --synth --std=08 --workdir=work top` |
| ตรวจความผิดพลาด | ดูข้อความใน log และเพิ่ม `--assert-level=error` |

### 7.3 ข้อเสนอสำหรับโปรเจกต์ของนักศึกษา

> ให้เขียนสคริปต์ที่ **ตรวจเครื่องมือที่มีในเครื่อง** แล้วเลือกวิธีรันที่ตรงกัน
> แบบที่คอร์สนี้ใช้อยู่แล้วคือ
> - `code/lab04/run.sh`, `code/lab14/run.sh`, `code/lab15/run.sh` — เลือก GHDL หรือ `vsim` อัตโนมัติ
> - `code/reference/questa/run.sh` — ตรวจด้วย GHDL เสมอ และตรวจด้วย Questa ถ้ามี

วิธีนี้ทำให้ผลของการตรวจสอบเหมือนกันทุกเครื่อง
ไม่ว่านักศึกษาจะมี license หรือไม่

## แบบฝึกหัดท้ายบท

1. รัน `ex00_counter_tutorial` ด้วย GHDL แล้วบันทึกไฟล์ `.ghw` และ `.vcd`
   จากนั้นเปิดดูด้วย GTKWave แล้วเทียบกับที่คาด
2. ตรวจ `$timescale` ในไฟล์ VCD ที่ได้ แล้วคำนวณว่าเวลา 76 ns เท่ากับกี่ fs
3. รัน `ex03_assert_severity` ด้วย GHDL ทั้งแบบมีและไม่มี `--assert-level=error`
   ที่ระดับ 2 แล้วเทียบรหัสออก
4. ทำตารางเทียบเทียบคำสั่งของ Questa กับ GHDL สำหรับงานที่คุณทำใน Lab ล่าสุด
5. อธิบายว่าทำไมการตรวจ marker จาก log สำคัญกว่าการพึ่งรหัสออกอย่างเดียว

---

## คำถามท้ายบท

1. GHDL และ Questa จัดการ library ต่างกันอย่างไร
2. ค่าเริ่มต้นของมาตรฐาน VHDL ต่างกันอย่างไรระหว่างสองเครื่องมือ
3. ผลของ `severity error` ต่างกันอย่างไร และมีผลกับการตั้งเกณฑ์ CI อย่างไร
4. GHDL เขียน waveform ได้ในรูปแบบใดบ้าง และเปิดดูด้วยเครื่องมือใด
5. ข้อเสนอสำหรับห้องเรียนที่มีและไม่มี license คืออะไร
