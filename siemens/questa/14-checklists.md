# บทที่ 14: เช็กลิสต์

> เช็กลิสต์ที่ใช้ได้จริงก่อนส่งงาน ก่อนเข้าเรียน หรือก่อนรันบน CI

**เครื่องมือที่เกี่ยวข้อง:** Questa SIM

## 1. เช็กลิสต์ก่อนเริ่มงาน

| # | รายการ | วิธีตรวจ | ผ่านเมื่อ |
|---|---|---|---|
| 1 | เครื่องมืออยู่ใน `PATH` | `vsim -version` | พิมพ์เวอร์ชันและหมายเลข build ออกมา |
| 2 | ใบอนุญาตใช้งานได้ | `lmutil lmstat -a` | เห็นรายการ feature ที่ใช้ได้ |
| 3 | เครื่องมือเป็นรุ่นที่รองรับมาตรฐานที่ใช้ | `vcom -help` | เห็นตัวเลือก `-2008` และ `-2002` |
| 4 | ไดเรกทอรีทำงานถูกต้อง | ดูพาธในหน้าต่าง Transcript | ตรงกับโฟลเดอร์ที่เก็บโค้ด |
| 5 | ไฟล์ตั้งค่า `.ini` ถูกต้อง | `vmap` | เห็นการผูก `work` ไปยังโฟลเดอร์ที่ถูกต้อง |
| 6 | มาตรฐาน VHDL เริ่มต้นเป็นค่าที่ต้องการ | อ่าน `VHDL93` ในไฟล์ `.ini` | เป็น `2002` สำหรับห้องเรียน |

## 2. เช็กลิสต์ก่อนคอมไพล์

| # | รายการ | วิธีตรวจ | ผ่านเมื่อ |
|---|---|---|---|
| 1 | context clause ครบทุก design unit | ไล่ดูทั้งไฟล์ | มี `library`/`use` ก่อนทุก `entity` และทุก `architecture` |
| 2 | ใช้ `ieee.numeric_std` | ค้นหา `std_logic_arith` | ไม่พบ |
| 3 | ลำดับคอมไพล์ถูกต้อง | ดูรายการไฟล์ | ไฟล์ `*_pkg.vhd` อยู่ก่อนไฟล์ที่ใช้ package |
| 4 | ไฟล์ไม่มี BOM | `Format-Hex <file> \| Select-Object -First 1` | ไบต์แรกเป็น `2D 2D` (`--`) หรือ `2D 2D` |
| 5 | ข้อความใน `report` เป็น ASCII | ค้นหาอักขระไทยในบรรทัด `report` | ไม่พบ |
| 6 | ไม่มีฟีเจอร์เฉพาะ VHDL-2008 | ตรวจรายการข้อห้ามใน `STYLE-CONTRACT.md` | ไม่พบ |
| 7 | คอมไพล์ด้วยทั้งสองมาตรฐาน | `vcom -2008` และ `vcom -2002` | ทั้งสองผ่านโดยไม่มีข้อผิดพลาด |

## 3. เช็กลิสต์ก่อนรัน

| # | รายการ | วิธีตรวจ | ผ่านเมื่อ |
|---|---|---|---|
| 1 | ไลบรารีถูกต้อง | `vmap` | `work` ผูกกับโฟลเดอร์ที่ใช้จริง |
| 2 | top-level ระบุครบ | ตรวจคำสั่ง `vsim` | ระบุ `work.<entity>` และ architecture ถ้ามีหลายอัน |
| 3 | generic ถูกต้อง | ตรวจ `-g` ที่ใช้ | ใช้เฉพาะ generic ของ entity ระดับบนสุด |
| 4 | testbench เป็น self-checking | อ่านโค้ด | มีการนับ error และพิมพ์ marker |
| 5 | มี watchdog | อ่านโค้ด | มี process ที่ยิง `TIMEOUT` เมื่อเกินเวลา |
| 6 | นาฬิกาหยุดเมื่อจบ | อ่านโค้ด | มี `when not done else '0'` |
| 7 | ไม่มี breakpoint ค้าง | `break` | รายการว่าง |
| 8 | สิทธิ์มองเห็นสัญญาณพอ | ตรวจ `+acc` | เพิ่ม `+acc` ถ้าต้องการ debug |

## 4. เช็กลิสต์หลังรัน

| # | รายการ | วิธีตรวจ | ผ่านเมื่อ |
|---|---|---|---|
| 1 | เจอ marker | `grep GOLDEN_ <log>` | พบ `GOLDEN_<ชื่อ>_PASS` |
| 2 | ไม่มี error | `grep -E "Error\|Failure" <log>` | ไม่พบ |
| 3 | ไม่มี assertion failure | `grep "assertion failure" <log>` | ไม่พบ |
| 4 | ไม่มีข้อความ timeout | `grep "TIMEOUT" <log>` | ไม่พบ |
| 5 | รหัสออกเป็นศูนย์ | `echo $?` | เป็น 0 |
| 6 | จำนวนจุดตรวจตรงกับที่คาด | อ่านข้อความใน marker | ตรงกับที่ระบุใน README |
| 7 | บันทึก log แล้ว | ตรวจโฟลเดอร์ `reports/` | มีไฟล์ log ของตัวอย่างนั้น |

## 5. เช็กลิสต์ก่อนส่งงาน

| # | รายการ | ผ่านเมื่อ |
|---|---|---|
| 1 | โค้ดคอมไพล์ผ่านทั้ง VHDL-2008 และ VHDL-2002 | คอมไพล์ผ่านทั้งสองโดยไม่มีข้อผิดพลาด |
| 2 | testbench เป็น self-checking | มี marker และ watchdog |
| 3 | ครอบคลุม corner case | มีเคส reset, ค่าขอบเขต, และค่า X |
| 4 | มี negative test | มีการทดสอบว่า testbench ล้มเหลวจริงเมื่อควรล้มเหลว |
| 5 | ข้อความใน marker บอกจำนวนที่ตรวจ | เช่น `12 check(s) passed` |
| 6 | สคริปต์รันได้ด้วยคำสั่งเดียว | `bash run.sh` ให้ผลสรุปที่ถูกต้อง |
| 7 | README อธิบายวิธีรันและผลที่ต้องเห็น | มีคำสั่งและตัวอย่างผลลัพธ์ |
| 8 | ไม่มีไฟล์ว่างหรือผลลัพธ์จำลอง | ทุกไฟล์มีเนื้อหาจริง |
| 9 | ไฟล์เป็น UTF-8 ไม่มี BOM | ตรวจด้วย `Format-Hex` |
| 10 | ไม่อ้างว่า "ผ่าน sign-off" | ใช้คำว่า "ผ่านเงื่อนไขของ flow ที่ใช้" แทน |

## 6. เช็กลิสต์สำหรับ CI

| # | รายการ | ผ่านเมื่อ |
|---|---|---|
| 1 | รันแบบไม่โต้ตอบ | ใช้ `vsim -c` และ `quit -f` หรือ `quit -code N` |
| 2 | มีรหัสออกที่ถูกต้อง | ตั้ง `onerror {quit -code 1}` และ `quit -code 0` เมื่อผ่าน |
| 3 | ตรวจ marker เพิ่มเติม | `grep` marker จาก log ไม่ใช่พึ่งรหัสออกอย่างเดียว |
| 4 | เก็บ log เป็น artifact | มีไฟล์ log ของตัวอย่างทุกตัว |
| 5 | ตั้ง `set -euo pipefail` | สคริปต์หยุดทันทีที่มีขั้นตอนล้มเหลว |
| 6 | ล้างไลบรารีก่อนรัน | แต่ละตัวอย่างได้ผลลัพธ์ไม่ขึ้นกับของที่ค้าง |
| 7 | เตรียมใบอนุญาตให้พร้อม | `LM_LICENSE_FILE` หรือ `LM_LICENSE_SERVER` ตั้งถูก |
| 8 | ทดสอบด้วยเครื่องมือสำรองได้ | ถ้าไม่มี license ให้ใช้ GHDL แทนได้ |

---

## แบบฝึกหัดท้ายบท

1. ทำเช็กลิสต์หัวข้อ 1 บนเครื่องที่ใช้ แล้วบันทึกผล
2. จงแก้โค้ดตัวอย่างให้ผิดเงื่อนไขของเช็กลิสต์ข้อใดข้อหนึ่งในหัวข้อ 2
   แล้วแสดงว่าเช็กลิสต์จับได้
3. ทำเช็กลิสต์หัวข้อ 4 กับ log ที่ได้จากการรันตัวอย่างทั้ง 4 ตัว
4. เขียนสคริปต์ CI ที่รันตัวอย่างทั้ง 4 ตัวและตรวจ marker ครบ
5. จงระบุว่าเช็กลิสต์ข้อใดที่สำคัญที่สุดสำหรับงานของคุณ และอธิบายเหตุผล

---

## คำถามท้ายบท

1. ทำไมต้องตรวจ BOM ของไฟล์ `.vhd`
2. รายการใดในเช็กลิสต์หัวข้อ 3 ที่พลาดแล้วระบบจะทำงานผิด
3. ทำไมต้องตรวจ marker ใน log แม้จะตรวจรหัสออกแล้ว
4. เช็กลิสต์ข้อใดในหัวข้อ 5 ที่มักถูกลืมในงานของนักศึกษา
5. ถ้าไม่มี license ใน CI จะทำตามเช็กลิสต์หัวข้อ 6 อย่างไร
