## 1. ปัญหาตอนติดตั้งและใบอนุญาต

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| `vsim` ไม่รู้จักคำสั่ง | `PATH` ไม่มีโฟลเดอร์ `bin` | เพิ่มโฟลเดอร์ลงใน `PATH` แล้วเปิด terminal ใหม่ |
| `license` หมดอายุหรือไม่พบ feature | ไม่มีใบอนุญาตที่เครื่องมือมองเห็น | `lmutil lmstat -a` แล้วตร้ง `LM_LICENSE_FILE` หรือ `LM_LICENSE_SERVER` |
| ใบอนุญาตใช้ได้บน Windows แต่ไม่ได้ใน WSL2 | ใบอนุญาตผูกกับ host name ของ Windows | ตรวจสอบกับผู้ดูแลระบบ ให้ใช้ license ของ WSL โดยเฉพาะ |
| `vsim` เปิดแล้วปิดทันที | ใบอนุญาตหมดอายุ | ตรวจด้วย `lmutil lmstat -a` |
| `Cannot write modelsim.ini` | โฟลเดอร์ติดตั้งเป็น read-only | ใช้ไฟล์ `.ini` ในไดเรกทอรีที่ทำงานแทน |

## 2. ปัญหาตอนสร้าง library

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| `vmap` เขียนไฟล์ไม่ได้ | โฟลเดอร์ติดตั้งเป็น read-only | สร้าง `modelsim.ini` ในไดเรกทอรีที่ทำงาน |
| `Unable to access library "work"` | ยังไม่ได้สร้าง library หรือ path ผิด | `vlib work` แล้ว `vmap work work` แล้วตรวจด้วย `vmap` |
| `library "xxx" not found` | ไม่ได้ผูกไลบรารีที่ต้องการ | `vmap xxx <พาธ>` แล้วตรวจด้วย `vmap` |
| ผูกไลบรารีแล้วยังหาไม่เจอ | พาธเป็นของเครื่องอื่น | ใช้พาธแบบสัมพัทธ์หรือแบบเต็มที่ถูกต้อง |
| `vdel` ลบไม่ได้ | ไฟล์ถูกล็อก | ปิดเครื่องมือที่เปิดไฟล์อยู่ก่อน |
| ไลบรารีเก่ายังอยู่ ทำให้ผลเพี้ยน | ไม่ได้ล้างก่อนรัน | `vdel -all -lib work` หรือลบโฟลเดอร์ `work` แล้ว `vlib` ใหม่ |

## 3. ปัญหาตอนคอมไพล์

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| `Unknown identifier "std_logic"` | context clause ครอบคลุมแค่ design unit เดียว | ประกาศ `library`/`use` ซ้ำก่อนทุก `entity` และทุก `architecture` |
| `String literal has a character with value 0x84` | มีอักขระไทยใน `report "..."` | ข้อความใน string literal ต้องเป็น ASCII ภาษาไทยใช้ได้เฉพาะในคอมเมนต์ |
| `invalid character, even in a comment` (GHDL) | คอมไพล์ด้วย `--std=93` แบบเข้ม ซึ่งรับเฉพาะอักขระชุดเดียวกับ VHDL-93 | เปลี่ยนเป็น `--std=02` หรือ `--std=08` หรือ `--std=93c` ดู[บทที่ 11](11-ghdl-cross-reference.md#3-มาตรฐาน-vhdl) |
| `package "xxx" not found` | คอมไพล์ผู้ใช้ package ก่อนคอมไพล์ package | คอมไพล์ `*_pkg.vhd` ก่อนเสมอ |
| `Operator "+" is not defined for type "STD_LOGIC_VECTOR"` | ไม่ได้ `use ieee.numeric_std.all` | เพิ่ม `use ieee.numeric_std.all;` |
| `(vcom-34) Signal "xxx" has multiple drivers` | มีสองจุดขับสัญญาณเดียวกัน | ตรวจโค้ดว่ามี concurrent assignment ทับกับ process หรือไม่ |
| ข้อความบอกว่าฟีเจอร์ไม่รองรับเมื่อใช้ `-2002` | ใช้ฟีเจอร์ของ VHDL-2008 | ดูตารางฟีเจอร์ที่ห้ามใช้ใน[บทที่ 3](03-compile-vhdl.md#23-กฎของคอร์สนี้) |
| `syntax error` ทันทีและไฟล์ดูถูกต้อง | ไฟล์มี BOM | ตรวจด้วย `Format-Hex <file> \| Select-Object -First 1` แล้วบันทึกใหม่แบบ UTF-8 without BOM |
| คอมไพล์ผ่านแต่โค้ดทำงานไม่ถูก | ใช้ `std_logic_arith` | เปลี่ยนเป็น `ieee.numeric_std` |

## 4. ปัญหาตอนโหลด design

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| `Unable to bind to entity "tb_xxx"` | ยังไม่ได้คอมไพล์ หรือชื่อผิด | ตรวจด้วย `vdir work` แล้วคอมไพล์ให้ครบ |
| โหลด entity ผิดตัวจากไลบรารีอื่น | ไม่ระบุไลบรารี | ระบุชื่อเต็ม `work.tb_xxx` |
| เลือก architecture ไม่ถูก | มีหลาย architecture ใน entity เดียว | ระบุ `work.tb_xxx(tb)` |
| ค่า generic ไม่เปลี่ยนตามที่สั่ง | ใช้ `-g` กับ generic ที่ไม่ใช่ของ entity ระดับบนสุด | ดู[บทที่ 4](04-load-and-elaborate.md#52-ข้อจำกัดที่สำคัญที่สุด) |
| `generic "xxx" not found` | พิมพ์ชื่อ generic ผิด | ตรวจชื่อใน `entity` |
| โหลดไม่ได้ทั้งที่คอมไพล์ผ่าน | คอมไพล์คนละมาตรฐาน | ล้างไลบรารีแล้วคอมไพล์ใหม่ทั้งหมด |
| `simulation failed` ทันที | ใช้ฟีเจอร์ VHDL-2008 ทั้งที่คอมไพล์ด้วย `-2002` | ตรวจรายการข้อห้ามใน `STYLE-CONTRACT.md` |

## 5. ปัญหาตอนจำลอง

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| simulation ไม่เดินเวลา | ไม่ได้สั่ง `run` | สั่ง `run -all` หรือ `run <เวลา>` |
| simulation ค้างไม่จบ | นาฬิกาใน testbench ไม่หยุด | ใช้ `clk <= not clk after PERIOD / 2 when not done else '0';` |
| ได้ค่าเป็น X ตลอด | สัญญาณไม่มี driver หรือขับพร้อมกันสองที่ | ดูหน้าต่าง Drivers |
| ค่าอ่านได้เป็นค่าเก่า | ไม่ได้รอ delta cycle | เพิ่ม `wait for 1 ns;` หรือ `wait until rising_edge(clk); wait for 1 ns;` |
| ค่าเกิดขึ้นทีหลังจากที่คาด | อ่านสัญญาณที่ถูก assign ด้วย `<=` ใน clocked process | ใช้ `variable` เก็บค่าใน process |
| simulation หยุดเองที่เวลาสั้น ๆ | เจอ breakpoint ที่ตั้งไว้ | เอา breakpoint ออกด้วย `break -delete` |
| ไม่เห็นข้อความ marker | ข้อความอยู่ในไฟล์ log อื่น | ตรวจว่า transcript เปิดอยู่และบันทึกลงไฟล์ที่ถูกต้อง |
| ข้อความใน log เป็นภาษาไทยที่อ่านไม่ออก | เครื่องมือแสดงผลแบบอักขระแทน | ข้อความใน `report` ต้องเป็น ASCII |

## 6. ปัญหาเรื่องการมองเห็นสัญญาณ

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| ไม่เห็นสัญญาณในหน้าต่าง Wave | การ optimize ตัดทิ้ง | เพิ่ม `+acc` ตอนโหลด design |
| ไม่เห็นสัญญาภายในโมดูล | ไม่ได้เพิ่มลงด้วย `add wave -r` | คลิกขวาที่ instance แล้วเลือก **Add Wave** |
| สัญญาณหายไปหลังจากจบการจำลอง | เป็นตัวแปรภายใน process | ใช้ signal ระดับโมดูลแทน |
| ค่าไม่เปลี่ยนตามที่คาด | ตั้ง breakpoint ผิดบรรทัด | ตรวจเลขบรรทัดในไฟล์จริง เลขบรรทัดของ VHDL ต่างจาก Verilog |
| ไฟล์ WLF ใหญ่เกินไป | บันทึกทุกสัญญาณตลอดการจำลอง | ใช้ `log -w <สัญญาณ> {<ช่วงเวลา>}` จำกัดช่วง |
| ไม่มีข้อมูลในไฟล์ WLF | ไม่ได้สั่ง `log` | ตรวจว่า transcript เปิดอยู่และใช้ `log -w` |

## 7. ปัญหาเรื่อง batch และ CI

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| คำสั่งรันค้างไม่จบ | ไม่มี `quit` ใน `-do` | เติม `quit -f` หรือ `quit -code 0` |
| รหัสออกเป็น 0 แม้มี error | ไม่ได้ตั้ง `onerror` | ตั้ง `onerror {quit -code 1}` |
| รหัสออกเป็น 1 แม้ผ่าน | `onbreak` ทำงานเมื่อเจอ breakpoint | เอา breakpoint ออกก่อนรันแบบ batch |
| ไม่มีไฟล์ log | ไม่ได้ใส่ `-l` | เพิ่ม `-l <ชื่อไฟล์>` |
| `can't find file` ตอนสั่ง `do` | พาธของไฟล์ `.do` ไม่ถูก | ใช้พาธสัมพัทธ์จากไดเรกทอรีที่รัน |
| `search` หา marker ไม่เจอ | `transcript off` | ใช้ `transcript file <ชื่อไฟล์>` และ `transcript on` |
| ผลของแต่ละตัวอย่างปนนกัน | รันทุกตัวใน session เดียว | แยก process ต่อหนึ่งตัวอย่าง |
| CI ไม่เห็นข้อผิดพลาด | ตรวจเฉพาะรหัสออก | ตรวจข้อความใน log ด้วยเสมอ |

## 8. เมื่อหาทางแก้ไม่เจอ

ลำดับการแก้ปัญหาที่แนะนำ

1. **เริ่มจากตัวอย่างที่ยังผ่าน** — ถ้า `ex00` ยังไม่ผ่าน
   แปลว่าปัญหาอยู่ที่สภาพแวดล้อม ไม่ใช่โค้ดของเรา
2. **ล้างไลบรารีแล้วคอมไพล์ใหม่ทั้งหมด** — กำจัดปัญหาไลบรารีเก่าทิ้ง
3. **ตรวจว่าโค้ดคอมไพล์ด้วยทั้งสองมาตรฐาน** — ช่วยแยกปัญหาออก
4. **ลดปัญหาให้เหลือตัวอย่างเดียว** — ตัด testbench ให้เหลือจุดที่ผิด
5. **ตรวจเวอร์ชันและไฟล์ตั้งค่า** — ค่า `VHDL93` และตัวเลือกอื่นอาจต่างจากที่คาด
6. **เก็บข้อมูลก่อนเปลี่ยนแปลง** — บันทึกคำสั่งที่รัน ข้อความใน Transcript
   และเวอร์ชัน เพื่อให้ถามผู้ช่วยหรือผู้ดูแลได้อย่างมีประโยชน์

> ถ้ายังแก้ไม่ได้ ให้เก็บรายละเอียด 4 อย่างนี้
> **คำสั่งที่รัน, ข้อความใน Transcript, เวอร์ชันของเครื่องมือ, และไฟล์ตั้งค่า .ini**
> จะทำให้การถามผู้ช่วยเร็วขึ้นมาก

## แบบฝึกหัดท้ายบท

1. จงทำให้ `ex00_counter_tutorial` พังอย่างใดอย่างหนึ่งใน 5 ข้อแรก
   แล้วหาสาเหตุจากตารางในบทนี้
2. ลบ context clause ของ architecture แล้วคอมไพล์ จดข้อความที่ได้
   แล้วกลับไปตรงตามตาราง
3. เพิ่ม `use ieee.std_logic_arith.all;` ในโค้ดแล้วคอมไพล์
   จดข้อความที่ได้ แล้วแก้กลับเป็น `numeric_std`
4. รันแบบ batch โดยไม่ใส่ `quit` แล้วสังเกตว่าเกิดอะไรขึ้น
   แล้วแก้โดยเติม `quit -code 0`
5. สร้าง testbench ที่มีนาฬิกาไม่หยุดเมื่อเสร็จ แล้วสังเกตว่า
   `run -all` ค้างอย่างไร แล้วแก้ให้หยุด

## คำถามท้ายบท

1. ทำไมการตรวจว่า `ex00` ยังผ่านอยู่จึงเป็นจุดเริ่มต้นที่ดี
2. อาการไหนบ้างที่บอกว่าเป็นปัญหาที่สภาพแวดล้อม ไม่ใช่ปัญหาโค้ด
3. ทำไมไฟล์ VHDL ที่มี BOM ถึงทำให้คอมไพล์ไม่ผ่าน
4. ทำไมต้องเพิ่ม `wait for 1 ns` หลังเปลี่ยนอินพุตของโมดูลแบบ combinational
5. เมื่อแก้ปัญหาไม่ได้ ต้องเก็บข้อมูลอะไรบ้างเพื่อขอความช่วยเหลือ
